## 1. ГЛАВНАЯ ТЕМА И РАЗРЕШЕНИЕ НА НОВЫЕ ТЕМЫ (BINDING)

1.1. ГЛАВНАЯ ТЕМА ПРОЕКТА: NEON STAGE DEFAULT SKIN-1.
   - Каноническая запись: SKIN-1 = NEON STAGE = DEFAULT = skin-053/Skin_053.
   - По УМОЛЧАНИЮ всегда: первый запуск плагина, reset, безопасный fallback.
   - NEON STAGE никогда не теряет позицию SKIN-1 и всегда первая в галерее.
   - Определение: дефолтная визуальная тема интерфейса плагина,
     использующая МИНИМАЛЬНЫЕ ресурсы CPU и RAM (см. раздел 11).
   - SOUND FORGE = NEON STAGE (отдельной темы SOUND FORGE не существует).
     SIGNAL FORGE как ИМЯ ТЕМЫ = NEON STAGE; как инженерный стандарт —
     остаётся стандартом, но имя темы не носит.
   - Термины «интерфейс», «тема», «скин», «графическая оболочка», «оболочка» —
     синонимы ОДНОГО объекта.

1.2. РАЗРЕШЕНИЕ СОЗДАВАТЬ НОВЫЕ ТЕМЫ (BINDING):
   - Новые темы разрешены и обязательны к созданию при необходимости.
   - Нумерация СТРОГО по порядку после SKIN-1: SKIN-2, SKIN-3, SKIN-4…
     без пропусков, дубликатов и перенумерации существующих ID.
   - Порядок в галерее = порядок нумерации; NEON STAGE DEFAULT всегда первая.
   - Релизная цель REV.18: ровно 16 тем — SKIN-1 NEON STAGE DEFAULT
     (без редизайна, по умолчанию) + SKIN-2…SKIN-16.
   - Каждая новая тема — ВАРИАЦИЯ единого стандарта NEON STAGE
     (палитра/артворк), а не чужая дизайн-система: все окна, панели и меню
     наследуют палитру/типографику/компоненты через ThemeManager::applyPalette.
   - Функциональность всех тем одинакова; различаются только палитра и артворк.
   - Legacy-имена реестра (Neon Riot, Dark Metal, Modern Studio, Carbon Relay,
     Blackout Voltage и т.д.) — исторические записи, НЕ активные темы;
     превращать их в новые «активные» темы, переименовывать или пересоздавать
     запрещено. Их судьба — только no-loss migration audit.
   - Имена SOUND FORGE / SIGNAL FORGE никакой новой теме не присваивать.

1.3. ПРАВИЛО АВТОДОПОЛНЕНИЯ (BINDING): если какого-то элемента темы,
   ассета или файла не хватает — модель ОБЯЗАНА создать его сама
   (автогенерация: на базе журнала Info.txt и макетов, при их отсутствии —
   с нуля, с пометкой [DECISION]). Разрешены любые инструменты и способы:
   генерация графики, SVG→PNG-конвейеры, скрипты генерации ассетов,
   палитровые токены, CRC-проверки, автоматическая валидация, векторные
   редакторы, оптимизаторы PNG, собственные промежуточные форматы —
   если итог совместим с runtime-контрактом скин-движка. Placeholder —
   только с явной пометкой, никогда не выдаётся за готовый ассет.
   Ограничения (не снимаются никаким инструментом): лицензионная чистота,
   прохождение валидации G1–G4 и PNG CRC, неизменность аудио-ядра и APVTS.

## 2. ПОЛНЫЙ СОСТАВ ТЕМЫ — ФАЙЛЫ, СПРАЙТЫ, АССЕТЫ (BINDING)

Каждая тема (включая SKIN-1) состоит из следующего полного набора.
Недостающий элемент любого класса — создать (п. 1.3).

2.1. РАСПОЛОЖЕНИЕ И КАРКАС:
   - Runtime-папка: ровно `Skins/` рядом с установленным .vst3 (НЕ AppData).
   - Папка темы: `Skins/<skin-id>/` (для главной: `Skins/skin-053/`).
   - Реестр тем: `Skins/theme_manifest.json` — живой registry всех тем
     (ID, имя, версия, порядок, active-пометка, пути к ассетам).
   - Контракт контролов: `Skins/control_schema.json` — 27 control-ID,
     21 палитровый токен, inventory (схема Skin Studio 52+).
     Legacy-схема theme.schema.json = Skin_01..51 — схемы НЕ взаимозаменяемы.
   - Описание темы: `theme.json` внутри папки темы — палитра, layout,
     маппинг контроллов, ссылки на ассеты, флаги (APVTS/layout/audio = false).

2.2. ГРАФИЧЕСКИЕ АССЕТЫ (PNG-мастера, максимум качества):
   - Контролы/спрайты: ≥512×512 на КАЖДЫЙ кадр состояния
     (default/hover/pressed/disabled/dragged — по состояниям каждого элемента).
   - Hero artwork (PLAYING CORE): мастер ≥1600×900, runtime 800×450.
   - Preview (карточка галереи): мастер ≥720×480, runtime 360×240.
   - Текстуры: ≥1024×1024, бесшовные (tileable).
   - Фон главного окна: ≥2560×1440.
   - Иконки точек входа TOP BAR: вектор-исходник (SVG) + PNG-экспорт
     нужных плотностей.
   - Мастера хранятся отдельно (master source), runtime-экспорт
     их НЕ перезаписывает.
   - Качество: без артефактов сжатия, размытия, мыльных апскейлов,
     водяных знаков, чужих логотипов; резкость на 100%, чистые края,
     палитра только из canonical tokens.

2.3. СЛОИ ЭФФЕКТОВ И АТЛАСЫ:
   - Baked-слои (PNG с альфой) для бликов, свечений, отражений, теней,
     градиентов, неоновых обводок, specular на металле/стекле —
     предрендерятся, НЕ пересчитываются шейдерами в кадре.
   - Texture atlas вместо дубликатов спрайтов (экономия RAM/GPU).
   - Все слои эффектов проходят ту же assets-регистрацию с CRC.

2.4. ПАЛИТРА И ТИПОГРАФИКА:
   - Ровно 21 HEX-токен палитры; zero hardcoded HEX в PluginEditor.cpp
     и Source/UI/* — только canonical tokens.
   - Контраст: primary ≥ 7:1 к окну (референс Skin_052: primary 17.81,
     secondary 10.79, disabled 5.23, LCD 17.17, accent 15.09).
   - Лицензионно-чистый шрифт; размеры типографики — по единой системе
     темы, без произвольных значений.

2.5. КОНТРОЛЬ И СБОРКА:
   - Валидация G1–G4: tools/validate_skin_pack.py; PNG CRC проходит G3.
   - Сборка/слияние пака: tools/merge_skin_pack.py (backup + атомарная запись).
   - Каждый ассет: имя, мастер-размер, runtime-размер, кадры спрайтов,
     слои эффектов, ресурсная стоимость, режим отображения
     (МИНИМАЛИЗМ дефолт / ЭФФЕКТЫ).

2.6. ТИПОВОЙ СОСТАВ ПАПКИ ТЕМЫ:
   Skins/<skin-id>/
     theme.json                 — палитра, layout, маппинг, флаги
     assets/controls/*.png      — спрайты контролов по кадрам состояний
     assets/hero/*.png          — hero artwork (мастер + runtime)
     assets/preview/*.png       — превью для галереи (мастер + runtime)
     assets/textures/*.png      — бесшовные текстуры ≥1024×1024
     assets/background/*.png    — фон ≥2560×1440
     assets/fx_layers/*.png     — baked-слои эффектов с альфой
     assets/icons/*.svg|png     — иконки TOP BAR и служебные
     fonts/                     — лицензионно-чистый шрифт
     atlas/                     — texture atlas + описание кадров

## 3. ПАЛИТРА И ЛЭЙАУТ
- Layout STUDIO_CONSOLE, сетка 12×16 (кратные ей размеры всех элементов).
- 27 control-ID parity между схемой и кодом (см. раздел 5).
- Единый источник света на всю тему; семантика цветов состояний:
  hover/active/disabled/success/warning/error — только из токенов.

## 4. ГЛАВНОЕ ОКНО — ЗОНЫ A–H
- A TOP BAR: SKINS | Import Guitar | Auto Discover | Curator | Settings |
  About — точки входа обязательны; нереализованное = disabled, честно.
- B BROWSER: пресеты, категории, поиск, статус.
- C PLAYING CORE: MELODY/PATTERN, hero artwork, 9 rotary.
- D FX CHAIN: 7 эффектов; on/off = реальный DSP routing.
- E AUTOCHORDS: HARMONY PRESETS, PLAYING STYLE/ARTICULATION, PLAYBACK MODE,
  RHYTHM MODE, Pattern Browser + 16 чипов (OPEN CHORDS, PALM MUTE,
  POWER CHORDS, DOWNSTROKE, ALTERNATE, CHUGS, SKANK, ARPEGGIO,
  STRAIGHT 8THS, FAST SKATE-PUNK, GALLOP, HALF-TIME, STOP-START,
  VERSE→CHORUS, OFFBEAT, OCTAVE HOOK); Selection независим для гармонии
  и ритма, визуально выделен; Display никогда не перекрывает MIDI-клавиатуру.
- F FX EDIT: одно окно, 8 страниц, 7 bypass (цель REV.18: 10–15 эффектов).
- G AMP & TONE: amp model, Gain/Bass/Treble — реальный тракт.
- H PERFORMANCE: read-only MIDI monitor.

## 5. СПРАВОЧНИК ЭЛЕМЕНТОВ УПРАВЛЕНИЯ (APVTS ID, вид, функция, поведение)

5.1. Ручки (9 rotary) — вид: круглая ручка с дугой значения и бликом
     (ЭФФЕКТЫ) / статичный честный указатель (МИНИМАЛИЗМ); drag по
     вертикали/дуге; двойной клик = сброс к дефолту; изменение двигает
     реальный параметр APVTS:
  ampGain 0..10 def 5 — гейн усилителя | eqHigh/eqMid/eqLow −12..12 def 0 —
  ВЧ/СЧ/НЧ | velocity 0..2 def 1 | dynamics 0..1 def 0.5 | swing 0..1 def 0 |
  humanize 0..1 def 0 | accent 0..1 def 0.75.

5.2. FX bypass (ровно 7, bool) — вид: тумблер с индикатором on/off
     (on = активная палитра, off = приглушённый); клик = реальный DSP-routing:
  compressorOn, eqOn, distortionOn, chorusOn, delayOn, reverbOn, cabinetOn.
  cabinetOn честно disabled без IR-ассетов. Восьмую кнопку (flanger)
  НЕ создавать.

5.3. Селекторы и служебные элементы:
  preset selector | category filter | preset search | LCD_display
  (единственный источник сообщений) | MELODY/PATTERN | sync selector |
  LOAD SFZ (=Import_Guitar) | patternSlot 0..7 (8 rhythm masks ≠ секции) |
  SKIN button (Ctrl+K — открывает галерею тем).

5.4. MIDI-клавиатура 36–84: подсветка = реальный MIDI-стейт
  (hover=warning, active=ledOn, search focus=highlight, FX success=success),
  клик = реальные ноты; подсветка с плавным затуханием.

5.5. Отсутствуют и НЕ изображать готовыми: PREV/NEXT/FAVORITE/SAVE пресетов,
  PUNK GROUP, LED-индикаторы, pitch/mod wheels, CPU/RAM meters.

## 6. ОКНА, ВКЛАДКИ, ПОВЕДЕНИЕ ПРИ ОТКРЫТИИ
- Пять auxiliary-окон (top-level DocumentWindow, native title bar off,
  JUCE bar = X + квадрат maximize/restore): FX EDIT (параметры выбранного
  эффекта) | AUTOCHORDS (disabled до backend) | IMPORT GUITAR (async SFZ:
  LOADING/SUCCESS/FAILURE через setStatus; drop-zone + Browse) | SETTINGS

  quality 2x/4x/8x/16x, Voices в пределах capacity, переключатель режима
  отображения) | PERFORMANCE (read-only).
- Геометрия tiled: 1=single, 2=2x1, 3–4=2x2, 5–6=2x3; нехватка места →
  focus paging; maximize = expanded через правый dock, не overlap.
- Persistence в PropertiesFile с clamp к work area; содержимое owned
  editor-side; X НЕ убивает состояние; hot-swap visual-only
  (hotSwapFadeMs=150, reduceInEco=true); аудиопатч не зависит от UI.

## 7. BROWSER И SKIN-ГАЛЕРЕЯ
- Галерея тем: cards/search/family/count/active marker. Клик сейчас
  немедленно грузит тему. Нет: Preview/Apply/Back/cancel, enlarged preview,
  Favorites, keyboard nav, persistence-тесты. Порядок доработки:
  selection state → Preview/Apply/Back → остальное.
- Preview темы в галерее = ассет preview (мастер ≥720×480).

## 8. RESIZE ОКНА (BINDING)
- Правый край → ширина; нижний край → высота; правый нижний угол → обе оси
  (живое перетаскивание).
- Содержимое масштабируется плавно и пропорционально вместе с окном:
  без обрезаний, наложений зон A–H и размытых апскейлов (ассеты из
  мастеров, не runtime-растягивание).
- Layout адаптируется по сетке 12×16; MIDI-клавиатура и AutoChords display
  никогда не перекрываются; размер сохраняется с clamp к рабочей области;
  при drag-resize — перерисовка по областям (экономная).

## 9. ЭФФЕКТЫ, АНИМАЦИИ, СОСТОЯНИЯ
- Эффекты (режим ЭФФЕКТЫ): блики, отражения, свечения (внешние и внутренние),
  тени, градиенты, неоновые обводки, specular — без бандинга, единый
  источник света. Цвета эффектов = производные canonical tokens.
- Анимации: hot-swap 150 мс, ручки/слайдеры с бликом и дугой, состояния
  hover/pressed/focus/dragged с easing, key-reactive подсветка клавиатуры,
  мягкие переходы FX и панелей, честная индикация загрузки.
- Ограничения: анимация отражает ТОЛЬКО реальное состояние — запрещено
  анимировать несуществующую активность (см. раздел 12); тяжёлый блюр —
  только baked-слои; ECO упрощает анимации (reduceInEco); бюджет —
  стабильные 60 FPS.

## 10. РАЗМЕРЫ И РЕНДЕРИНГ
- Минимумы мастеров — см. раздел 2.2 (контролы ≥512×512/кадр, hero
  ≥1600×900, preview ≥720×480, текстуры ≥1024×1024, фон ≥2560×1440).
- Окна: минимум под читаемость всех зон A–H; clamp к рабочей области.
- HiDPI 100–400% строго по реальному масштабу экрана; 4K/8K и
  мультимонитор — по необходимости с минимальными затратами.

## 11. РЕСУРСЫ И РЕЖИМЫ ОТОБРАЖЕНИЯ (BINDING)
- ДЕФОЛТ = МИНИМАЛИЗМ: чистый стандартный вид БЕЗ доп. эффектов/анимаций;
  минимальное потребление CPU, RAM, графической памяти и видеоядра.
  Первый запуск, сброс и fallback всегда открываются в минимализме.
- «ЭФФЕКТЫ» — полный премиум-вид из раздела 9; включается только выбором
  пользователя (SETTINGS + быстрый доступ из SKIN-меню); сохраняется между
  сессиями; НИЧТО не переключается самовольно.
- Минимализм — НЕ другая тема, а режим отображения той же единой темы
  NEON STAGE DEFAULT SKIN-1: палитра, layout и состав контролов идентичны.
- Максимальные ресурсы НЕ используются по умолчанию; качество достигается
  инженерией (baked-слои, atlas, кэширование, repaint по областям).
  Правило: МАКСИМУМ КАЧЕСТВА на единицу ресурсов, МИНИМУМ абсолютного
  потребления — одновременно.
- CPU: без busy-wait и избыточных таймеров; анимации 30–60 Гц по
  необходимости; приостановка repaint при свёрнутом редакторе.
- GPU: рендеринг только при изменениях; статичные слои кэшируются.
- Память: lazy loading, LRU, atlas, фиксированные лимиты кэшей,
  отсутствие утечек Image/LookAndFeel/Component.

## 14. ФОРМАТ ВЫДАЧИ
1. Полные файлы темы: theme.json + манифесты — без «...».
2. Таблица «элемент → APVTS ID → координаты/токен».
3. Список ассетов: имя, мастер-размер, runtime-размер, кадры спрайтов,
   слои эффектов, ресурсная стоимость, режим отображения.
4. Недостающие ассеты — СОЗДАННЫ (не перечислены как «нужны»), либо
   честно помечены как placeholder с планом перегенерации.
5. Чек-лист: G1–G4 / PNG CRC / контрасты ≥ 7:1.
6. Честный итог: что реализовано, что — цель; точный next step.
7. Метки [DECISION] при создании с нуля.
