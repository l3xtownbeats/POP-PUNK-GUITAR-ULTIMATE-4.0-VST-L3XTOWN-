## 4. Как закрыты известные конфликты из прежних записей

1. Skin_052 / registry mismatch (CTest 11/12, run #860): registry содержит все 52 темы,
   валидатор берёт количество из registry, магическое число 50/51 удалено.
2. C1083 BinaryData (§16.1): обе binary-цели объявлены РАНЬШЕ зависимых; уникальные
   HEADER_NAME (PPGUData.h / PPGUTestData.h), NAMESPACE без HEADER_NAMESPACE;
   pre-configure gate блокирует pipeline до сборки.
3. R14 runtime layout: workflow формирует sibling Skins/ рядом с VST3 и проверяет ≥52 папок.
4. JUCE 7 String API (fromWideCharPointer/trimStartCharacters): в PluginEditor
   не используются; SFZ-путь обрабатывается через juce::String напрямую.
5. assert-in-Release (AuxiliaryPanelLayout tests): все проверки переведены на
   собственный CHECK с ненулевым exit code.
6. Worker-after-exception: loader-поток публикует только полный immutable Bank;
   частичные состояния никогда не становятся видимыми аудиопотоку.
7. Панели как независимые окна: AuxiliaryPanelManager владеет окнами; закрытие
   сохраняет контент/состояние; tileAll раскладывает все открытые панели без перекрытий.

## 5. Открытые гейты (честно, без присвоения PASS)

2. FL Studio 20 host acceptance: load, MIDI note on/off, preset recall, state restore,
   длительная стабильность.
3. CPU/RAM profiling и listening count N/300 — только измерениями.
4. JUCE 7.0.12/CMake 3.22 → JUCE 8/CMake ≥3.24 (REV 13 §13.2) — отдельный этап.

## 6. Сборка

```
cmake -S . -B build -A x64 -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```
Установка: .vst3 → C:\Program Files\Common Files\VST3\; каталог Skins/ — рядом с bundle.
