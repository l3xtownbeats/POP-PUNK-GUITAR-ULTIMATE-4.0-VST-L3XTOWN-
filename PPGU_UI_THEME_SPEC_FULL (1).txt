## РАЗДЕЛ 1. ТЕМА-СТАНДАРТ
1. ЕДИНАЯ ТЕМА-СТАНДАРТ: NEON STAGE DEFAULT SKIN-1 — дефолтная визуальная
   тема интерфейса плагина с использованием минимальных ресурсов CPU RAM.
   «Интерфейс» = «тема» = «скин» = «графическая оболочка» — ОДИН объект.
2. Каноническая запись: SKIN-1 = NEON STAGE = DEFAULT = skin-053/Skin_053.
   Всегда: default при первом запуске, reset target, безопасный fallback.
3. SOUND FORGE = NEON STAGE (единая тема). SIGNAL FORGE как ИМЯ ТЕМЫ =
   NEON STAGE; как инженерный стандарт — остаётся стандартом.
4. Нумерация остальных тем: строго SKIN-2, SKIN-3, SKIN-4… без пропусков,
   дубликатов и перенумерации. Порядок галереи = порядок нумерации.
5. Релизная галерея: ровно 16 тем — SKIN-1 NEON STAGE DEFAULT (первая,
   по умолчанию, без редизайна) + SKIN-2…SKIN-16.
6. Legacy-имена реестра (Neon Riot, Dark Metal, Modern Studio, Carbon
   Relay, Blackout Voltage) — исторические записи, НЕ активные темы.
   Разрешён только no-loss migration audit; переименование запрещено.
   Legacy fallback до миграции: Skin_051 Blackout Voltage.
7. Все окна/панели/меню наследуют палитру NEON STAGE через
   ThemeManager::applyPalette — единая дизайн-система во всех окнах.

## РАЗДЕЛ 2. ПАЛИТРА И ЛЭЙАУТ
1. 21 HEX token. ZERO hardcoded HEX в PluginEditor.cpp и Source/UI/* —
   только canonical tokens.
2. Контраст primary ≥ 7:1 к окну. Референсные значения Skin_052 Carbon
   Relay: primary 17.81, secondary 10.79, disabled 5.23, LCD 17.17,
   accent 15.09.
3. Layout: STUDIO_CONSOLE, сетка 12×16.
4. Цвета свечений/бликов = производные canonical tokens, не свободные HEX.
5. Семантика состояний: hover=warning, active=ledOn, search
   focus=highlight, FX success=success.

## РАЗДЕЛ 3. РАЗМЕРЫ ОКОН И ЭЛЕМЕНТОВ
1. Геометрия окон: tiled — 1 окно = single; 2 = 2x1; 3–4 = 2x2; 5–6 = 2x3.
   Нехватка места → focus paging, не overlap. Maximize = expanded через
   правый dock, не overlap.
2. Минимальные границы окна: обеспечивают читаемость всех зон A–H;
   размер и позиция сохраняются в PropertiesFile с clamp к рабочей
   области (work area) монитора.
3. Мультимонитор: корректная работа при разных DPI/частотах; геометрия
   с clamp к рабочей области.
4. Масштаб содержимого: экран плавно увеличивается и уменьшается вместе
   с окном (см. раздел RESIZE).
5. Минимальные размеры МАСТЕР-ассетов (спрайты, иконки, текстуры):
   - контролы/спрайты: ≥ 512×512 на кадр;
   - hero artwork: ≥ 1600×900 (runtime 800×450);
   - preview: ≥ 720×480 (runtime 360×240);
   - текстуры: ≥ 1024×1024, бесшовные;
   - фон: ≥ 2560×1440.
   Мастера хранятся отдельно, runtime-экспорт их не перезаписывает.
6. Runtime-масштабирование: рендер строго по реальному масштабу экрана
   (HiDPI 100–400%) из мастер-ассетов; никогда не рендерить в большем
   разрешении, чем нужно; без мыльных апскейлов.
7. Точные пиксельные размеры кнопок/ручек в макете задаются сеткой 12×16
   (модульная привязка); если в макете размер не указан — [DECISION] и
   пропорции по сетке, единые для всех элементов одного типа.

## РАЗДЕЛ 5. СПРАВОЧНИК ЭЛЕМЕНТОВ УПРАВЛЕНИЯ
### 5.1 Ручки (9 rotary) — ID, диапазон, дефолт, функция
- ampGain 0..10 def 5 — гейн усилителя (зона C).
- eqHigh / eqMid / eqLow −12..12 def 0 — ВЧ/СЧ/НЧ-эквалайзер (зона G).
- velocity 0..2 def 1 — сила/динамика взятия ноты.
- dynamics 0..1 def 0.5 — динамический отклик.
- swing 0..1 def 0 — свинг ритма.
- humanize 0..1 def 0 — «человечность» исполнения (разброс).
- accent 0..1 def 0.75 — акцентная доля.
ВИД: круглая ручка с дугой значения и бликом в режиме ЭФФЕКТЫ; статичный
  честный указатель в МИНИМАЛИЗМЕ.
ПОВЕДЕНИЕ: drag по вертикали/дуге; двойной клик = сброс к дефолту;
  изменение двигает реальный параметр APVTS (аудио-эффект настоящий).

### 5.2 FX-кнопки (ровно 7, bool)
compressorOn | eqOn | distortionOn | chorusOn | delayOn | reverbOn |
cabinetOn — тумблеры с индикатором on/off. Клик = реальный DSP-routing.
cabinetOn честно disabled без реальных IR-ассетов и convolution path.
flangerOn есть в процессоре, но НЕ в inventory: страница есть,
enable-переключателя нет — ВОСЬМОЙ switch НЕ СОЗДАВАТЬ.

### 5.3 Селекторы и служебные элементы
- preset selector — выбор пресета из BROWSER.
- category filter — фильтр категорий пресетов.
- preset search — поиск; focus подсвечивает клавиатуру (highlight).
- status label (=LCD_display) — ЕДИНСТВЕННЫЙ источник сообщений/статусов.
- MELODY / PATTERN — режимы игры (PUNK GROUP в playMode отсутствует).
- sync selector — синхронизация с темпом хоста.
- LOAD SFZ (= Import_Guitar) — импорт SFZ-инструмента.
- SKIN button (Ctrl+K) — открытие SKIN-галереи.
- patternSlot 0..7 — 8 rhythm masks (НЕ секции; section-first UX — gap).
- MIDI keyboard 36–84 — клик = реальные ноты; подсветка ТОЛЬКО по
  реальному MIDI-стейту: hover=warning, active=ledOn, search
  focus=highlight, FX success=success. Плавное затухание подсветки.

### 5.4 TOP BAR — шесть точек входа
SKINS (галерея), Import Guitar, Auto Discover, Curator, Settings, About.
Нереализованные — disabled; не имитировать работу.

### 5.5 Чипы AUTOCHORDS (16)
Каждый кликабелен, выбранный визуально выделен. Selection независим
для гармонии и ритма. До backend — setup-only (без генерации MIDI).

### 5.6 ОТСУТСТВУЮТ И НЕ ИЗОБРАЖАТЬ ГОТОВЫМИ
PREV/NEXT/FAVORITE/SAVE пресетов, BPM, transport, метры, pitch/mod
wheels, LED-индикаторы, CPU/RAM-метры. Полный список — раздел ЗАПРЕЩЕНО.

## РАЗДЕЛ 8. RESIZE ОКНА И МАСШТАБИРОВАНИЕ ЭКРАНА (BINDING)
1. Окно меняет размер при перетаскивании: правый край → ширина; нижний
   край → высота; правый нижний угол → обе оси сразу (живой resize в
   реальном времени, без лагов).
2. Экран (содержимое) УВЕЛИЧИВАЕТСЯ и УМЕНЬШАЕТСЯ вместе с окном: контент
   масштабируется плавно и пропорционально — без обрезания, без наложений
   зон A–H, без перекрытия MIDI-клавиатуры, без мыльных апскейлов.
3. Адаптация layout — по сетке 12×16 и правилам tiled/focus paging;
   при нехватке места — focus paging, не overlap.
4. При drag-resize — экономная перерисовка изменённых областей, не полный
   repaint каждый кадр.

## РАЗДЕЛ 10. ЭФФЕКТЫ, АНИМАЦИИ, АССЕТЫ
1. Эффекты максимального качества (режим ЭФФЕКТЫ): блики, отражения,
   свечения (внешние/внутренние), тени, градиенты, неоновые обводки,
   specular на металле/стекле — без бандинга, единый источник света.
2. Живые анимации: плавный hot-swap 150 мс; анимация ручек/слайдеров
   с бликом и дугой значения; hover/pressed/focus/dragged с easing;
   key-reactive подсветка клавиатуры с затуханием; мягкие переходы
   состояний FX и панелей; честная индикация загрузки.
3. Ограничения: анимация отражает ТОЛЬКО реальное состояние; тяжёлый
   блюр/шейдеры предрендерятся в baked-слои (PNG с альфой), не считаются
   в кадре; ECO упрощает анимации (reduceInEco); бюджет — стабильные
   60 FPS (при конфликте сначала профилирование).
4. Качество ассетов: без артефактов сжатия, размытия, апскейлов,
   водяных знаков, чужих логотипов. Контроль: резкость на 100%, чистые
   края, палитра только из canonical tokens.
5. Placeholder-графика — только с явной пометкой; никогда не выдаётся
   за готовый ассет. Недостижимое качество — максимум возможного + явный
   список ассетов на перегенерацию.

## РАЗДЕЛ 11. РЕЖИМЫ ОТОБРАЖЕНИЯ И РЕСУРСЫ (BINDING)
1. Выбор из НЕСКОЛЬКИХ вариантов графики интерфейса:
   «ЭФФЕКТЫ» — полный премиум-вид (все эффекты и анимации);
   «МИНИМАЛИЗМ» — чистый стандартный вид по макету, без доп. эффектов.
2. ДЕФОЛТ = МИНИМАЛИЗМ: первый запуск, сброс и fallback всегда открываются
   в минимализме с минимальным потреблением CPU, RAM, графической памяти
   и видеоядра.
3. Переключатель: в SETTINGS + быстрый доступ из SKIN-меню; сохраняется
   между сессиями; НИЧТО не переключается самовольно.
4. Минимализм — НЕ другая тема, а режим ЕДИНОЙ темы NEON STAGE DEFAULT
   SKIN-1: палитра, layout и состав контролов идентичны; различаются
   только слои эффектов/анимаций.
5. Ресурсы по умолчанию — МИНИМАЛЬНЫЕ. Максимальные ресурсы НЕ
   используются без явной необходимости. Доступно, но только по
   необходимости: GPU-ускорение (при измеримом выигрыше, честный fallback
   на software), HiDPI 100–400%, 4K/5K/8K, антиалиасинг/субпиксельные
   шрифты/32-битный цвет.
6. Энергоэффективность: минимум потребления в любых состояниях (включая
   простой и свёрнутый редактор); анимации 30–60 Гц по необходимости;
   repaint только изменённых областей; рендеринг только при изменениях;
   lazy loading, LRU-кэши с лимитом, texture atlas; отсутствие утечек;
   эффективность подтверждается замерами FPS/RAM/CPU, а не декларациями.
7. Правило: МАКСИМУМ КАЧЕСТВА на единицу ресурсов, МИНИМУМ абсолютного
   потребления — оба одновременно (качество достигается инженерией).
8. ECO-профиль: максимально снижает частоту кадров/анимации/эффекты без
   разрушения идентичности темы.

## РАЗДЕЛ 14. ФОРМАТ ВЫДАЧИ ПО ТЕМЕ
1. Полный theme.json (токены, layout, флаги).
2. Таблица «элемент → APVTS ID → координаты/токен».
3. Список ассетов: имя, мастер-размер, runtime-размер, кадры спрайтов,
   слои эффектов, режим отображения (МИНИМАЛИЗМ дефолт / ЭФФЕКТЫ),
