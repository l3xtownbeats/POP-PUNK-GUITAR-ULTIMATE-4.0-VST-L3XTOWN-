## 1. Назначение и продукт

POP PUNK GUITAR ULTIMATE — VST3-инструмент для Windows x64, целевая DAW — FL Studio 20. Приоритеты: безопасность → realtime → звук → ресурсы → UX. Цели CPU/RAM и готовность к коммерческому релизу подтверждаются только измерениями и тестами.

## 3. Подтверждённая техническая база и риски

Последний углублённый аудит SamplePool/SamplerEngine подтвердил:
- загрузка SFZ строит candidate snapshot и публикует его атомарно после проверки generation token;
- старые snapshots и streaming services удерживаются до уничтожения SamplePool для защиты активных raw pointers;
- текущие ограничения: до 128 snapshots и до 8 streaming library roots на экземпляр;
- SamplerEngine содержит 64 заранее выделенных voice slots;
- cache miss не должен блокировать audio thread; voice удерживает cursor до получения страницы;
- streaming worker дренирует очередь при штатной остановке;
- после исключения worker автоматически не восстанавливается.

Открытые инженерные риски:
1. безопасное освобождение старых snapshots без use-after-free;
2. совокупная память/потоки при нескольких streaming roots;
3. политика восстановления после падения streaming worker;
4. стресс 64 voices при cache pressure, queue overflow и loop prefetch;
5. cancellation/lifetime гонки при загрузке и уничтожении processor;
6. полная Windows Release + CTest + pluginval проверка после изменений.

Нельзя удалять старые snapshots простым сбросом unique_ptr, пока не доказано quiescence всех audio readers.

## 4. Архитектура семейства Guitar / Bass

Принято: один общий низкоуровневый PPGU Audio Engine и два самостоятельных продукта — Guitar Edition и Bass Edition. Общими могут стать streaming, WAV/SFZ reader, cache, queues, state/preset infrastructure, MIDI primitives, FX infrastructure и QA. Guitar/Bass артикуляции, SoundBank, presets, product identity и UI-профили остаются раздельными. Это архитектурное решение, не готовая реализация.

## 5. REV 10.1 — SOUND HUNTER

Зафиксировано в `docs/PPGU_REV_10_1_SOUND_HUNTER_RU.md`:
- GREEN/YELLOW/RED проверяются на уровне каждого конкретного asset; сайт сам по себе не гарантирует лицензию;
- AUTO ADD — только для подтверждённых CC0/PD файлов с provenance, SHA-256, техническим screening и guitar-only gate;
- YELLOW — ручной импорт; RED — исключён;
- DEEP SEARCH расширяет существующий S6.5 pipeline, второй pipeline запрещён;
- сетевые операции и анализ файлов выполняются вне audio callback;
- GOLD требует технической проверки и человеческого прослушивания; COPYRIGHT SUSPECT блокирует commit;
- MELODY 30 / PATTERN 50 / PUNK GROUP 40 — цели, не достигнутые показатели.

Статус: DESIGNED. DeepSearchWorker, StyleClassifier, CuratorPanel, GREEN registry, новые проверенные звуки и H9 tests ещё не подтверждены как реализованные.

## 6.1. SOUND HUNTER — licensing/provenance contract foundation (2026-11-11)

Аудит текущего main не обнаружил production DiscoveryEngine, BankScanner, S6.5 registry или отдельного Discovery source tree. Поэтому второй search/import pipeline не создавался; сделан только изолированный policy-contract foundation перед интеграцией в существующий S6.

Добавлено:
- tools/validate_sound_asset_registry.py — проверка asset-level GREEN/YELLOW/RED записей и вычисляемого AUTO ADD gate;
- assets/sound_hunter/registry.json — versioned registry, пока пустой;
- tests/TestSoundAssetRegistry.py — 12 unit cases для GREEN, YELLOW, RED, direct-download, hash, license evidence, copyright suspect, guitar gate, quality, GOLD listening, duplicate IDs и empty registry;
- CTest target ppgu_sound_asset_registry_contract зарегистрирован в CMake.

GREEN AUTO ADD требует: подтверждённый CC0/PD allowlist, сохранённое license evidence, APPROVED legal review, разрешение commercial use/redistribution/modification, прямую загрузку, совпадающий SHA-256, SNR >=40 dB, отсутствие clipping, DC offset <=0.0001, integrity PASS, GUITAR_CONFIRMED, profile и отсутствие copyright/manual-review flags. YELLOW остаётся manual-only; RED не может быть curator-overridden; GOLD требует human listening approval.

Коммиты этапа:
- a739303 — policy validator;
- 413842c — policy unit tests;
- 18396a4 — пустой versioned registry;
- 222e9aa — защита валидатора от malformed values;
- 00869e6 — CTest registration.

Статус: POLICY CONTRACT IMPLEMENTED IN TOOLING; НЕ интегрирован в production S6/DiscoveryEngine, не выполняет поиск/скачивание и не добавляет звуки. Registry пуст, approved assets = 0. CTest/Windows Release/pluginval для этого HEAD ещё не подтверждены; ожидается GitHub Actions run после текущих изменений.
