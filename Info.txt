## 3. Подтверждённая техническая база и риски

Последний углублённый аудит SamplePool/SamplerEngine подтвердил:
- загрузка SFZ строит candidate snapshot и публикует его атомарно после проверки generation token;
- старые snapshots и streaming services удерживаются до уничтожения SamplePool для защиты активных raw pointers;
- текущие ограничения: до 128 snapshots и до 8 streaming library roots на экземпляр;
- SamplerEngine содержит 64 заранее выделенных voice slots;
- cache miss не должен блокировать audio thread; voice удерживает cursor до получения страницы;
- streaming worker дренирует очередь при штатной остановке;
- после исключения worker автоматически не восстанавливается.

Открытые инженерные риски:
1. безопасное освобождение старых snapshots без use-after-free;
2. совокупная память/потоки при нескольких streaming roots;
3. политика восстановления после падения streaming worker;
4. стресс 64 voices при cache pressure, queue overflow и loop prefetch;
5. cancellation/lifetime гонки при загрузке и уничтожении processor;
6. полная Windows Release + CTest + pluginval проверка после изменений.

Нельзя удалять старые snapshots простым сбросом unique_ptr, пока не доказано quiescence всех audio readers.

## 4. Архитектура семейства Guitar / Bass

Принято: один общий низкоуровневый PPGU Audio Engine и два самостоятельных продукта — Guitar Edition и Bass Edition. Общими могут стать streaming, WAV/SFZ reader, cache, queues, state/preset infrastructure, MIDI primitives, FX infrastructure и QA. Guitar/Bass артикуляции, SoundBank, presets, product identity и UI-профили остаются раздельными. Это архитектурное решение, не готовая реализация.

## 2026-11-12 — C1083 / generated BinaryData.h regression fix

**Статус:** SOURCE FIX COMMITTED; WINDOWS BUILD PENDING.  
Source commit: `0ef0ebe934350d57779328a5e0979f1134ae85f2` (parent: `e21980eee5289b00db371b3c2a907a5d0016b19a`).

В `CMakeLists.txt` добавлена отдельная JUCE binary-data цель `PPGUTestData` до создания зависимого integration-test target. Цель использует маленький нейтральный fixture `tests/assets/ppgu_test_data.txt`, namespace `PPGUTestData` и линкуется непосредственно к `ppgu_processor_pattern_tests`. Это обеспечивает generated include directory и `JUCE_TARGET_HAS_BINARY_DATA` для test target в чистом build tree.

**Важное уточнение JUCE API:** в закреплённой проектом JUCE 7.0.12 сигнатуре используется аргумент `NAMESPACE`, а не `HEADER_NAMESPACE`; сгенерированный заголовок по умолчанию называется `BinaryData.h` и попадает в include directory target. Поэтому путь `PPGUTestData/BinaryData.h` из чернового примера REV 13 не используется: JUCE добавляет generated header через `JuceHeader.h` при наличии `JUCE_TARGET_HAS_BINARY_DATA`. Основание: JUCE CMake API и реализация `juce_add_binary_data`.

GitHub Actions run #827 / ID `43113647167` создан на source commit `0ef0ebe934350d57779328a5e0979f1134ae85f2`; на момент записи состояние `queued`. Локальная Windows/MSVC Release-сборка в этой среде не выполнялась. Следовательно, исправление пока **не объявляется BUILT или TESTED**. Следующие гейты: полный build всех targets, CTest, locate VST3, pluginval strictness 5 и packaging.

Отдельное расхождение REV 13 для последующего согласования: текущий root CMake всё ещё закрепляет JUCE 7.0.12 и minimum CMake 3.22; REV 13 §13.2 требует JUCE 8 и CMake >=3.24. Версии не менялись в рамках изолированного C1083 fix, чтобы не смешивать причины сборочных регрессий.

## 2026-11-12 — PATTERN guitar / tone / articulation workflow clarification

Approved user clarification: PATTERN workflow is separated into three independent choices:
1. Guitar/instrument source (electric/acoustic and available recorded instrument profile).
2. Tone preset (e.g. Pop Punk Lead, Punk Rock Rhythm, Clean/Crunch/Drive, Flanger or Tremolo tone); tone and FX do not replace performance changes.
3. Performance articulation/variation (open strum, lead/octave hook, palm mute/tight, muted bridge, sustain/ambient, tremolo picking, arpeggio, stop-start/syncopated, downstroke, alternate down-up), limited to articulations backed by real recordings.

User's primary functionality references: Native Instruments Session Guitarist Electric Sunburst Deluxe and Vintage; Neon is an additional reference. Tom DeLonge's Blink-182 / Angels & Airwaves performance vocabulary is an inspiration target for original patterns (driving downstrokes, power chords, octave hooks, palm-muted verses, open chorus lift and sustained/ambient lead textures), not permission to copy recordings, riffs or proprietary presets.

PATTERN variations must be switchable during playback with host sync and clean transitions. Optional compatible layering may be an advanced feature; it must not be the default behavior and must respect CPU/polyphony limits. Tone effects (flanger, tremolo effect, delay, reverb, distortion) are distinct from playing techniques (tremolo picking, palm mute, strumming, etc.). Every displayed articulation requires a matching recorded performance/one-shot/loop map and runtime verification; unavailable articulations must be marked unavailable rather than simulated with synthetic guitar.

Specification updated in `docs/MASTER_PRODUCT_SPEC_4_0_RU.md` §15.7. This is an approved product requirement, not evidence that the runtime UI, sample maps or playback engine already implement it.

## 9. SOUND FORGE — ресурсный контракт (2026-11-12)

Пользователь утвердил приоритет: расширять и улучшать гитарную библиотеку без заметного роста потребления CPU, RAM, диска и энергии компьютера/ноутбука. SOUND FORGE проектируется как offline/non-realtime подготовка материалов, а не как тяжёлая обработка внутри игрового движка.

### 9.1 Разделение runtime и подготовки
- VST3 runtime отвечает за воспроизведение уже подготовленных инструментов; сканирование каталогов, конвертация, ресемплинг, анализ, fingerprinting, хэширование и пакетная обработка запрещены в audio callback.
- SOUND FORGE выполняет импорт/конвертацию/улучшение вне DAW realtime path: предпочтительно отдельный companion/curator process или явный пользовательский offline job. Пока отдельный production target не реализован, не заявлять наличие готового SOUND FORGE.
- Не запускать фоновые анализаторы при открытии плагина без явного запроса пользователя. Не держать постоянно активный worker ради неиспользуемой библиотеки.
- Исходники сохраняются неизменными; все производные файлы версионируются и могут быть пересозданы.

### 9.2 Бюджет игрового движка
- Сохранять текущую bounded streaming архитектуру: 64 заранее выделенных voice slots, максимум 8 streaming roots, 256 cache slots на root, 4096 frames/page. При stereo float это около 8 MiB cache/root и до 64 MiB суммарно для восьми roots; это верхняя граница только page cache, не полная RAM плагина.
- Не увеличивать эти лимиты без профилирования на целевых Windows 10 x64 системах и сравнительных измерений.
- Не декодировать целые библиотеки в RAM; использовать существующий metadata index и bounded page streaming. Не создавать thread-per-sample/voice/preset.
- Не добавлять обязательный neural/AI denoising, oversampling или постоянные спектральные анализаторы в realtime path.
- Конвертировать в заранее выбранный playback format один раз offline; не ресемплировать файлы каждый раз при старте ноты или смене пресета.
- Не делать лишних копий буферов. Любые новые кэши должны иметь фиксированный лимит, явную политику eviction и измеряемый worst-case.

### 9.3 Бюджет SOUND FORGE offline
- По умолчанию один активный job и ограниченная очередь; concurrency configurable, default 1. Pause/cancel/resume обязательны для длительных задач.
- Обработка блоками/чанками, а не загрузка всех исходников в память. Память ограничивается размером рабочих буферов и небольшим числом одновременно открытых файлов.
- При работе от батареи — режим LOW POWER: один worker, отсутствие параллельных fingerprint/preview задач, возможность приостановки. Не использовать GPU как обязательную зависимость.
- Предпрослушивание использует тот же bounded playback path; не запускать несколько скрытых preview streams.
- Disk quota и free-space preflight обязательны; временные файлы очищаются при отмене/ошибке, оригиналы не перезаписываются.

### 9.4 Качество и измерения
- Улучшение не должно означать безусловное шумоподавление/нормализацию: сохранять атаку, динамику, transient, естественный шум инструмента и фазу; каждое преобразование сравнивается с оригиналом A/B.
- Lossless conversion по умолчанию. Lossy source не повышается фиктивно до lossless quality; sample-rate conversion не объявляется улучшением исходного качества.
- Для каждого этапа фиксировать wall time, peak working-set/RAM, CPU time/load, bytes read/written, число worker threads и итоговый размер. Сравнивать с baseline текущего HEAD на одном и том же компьютере/настройках.
- Release gate: никаких заявлений «потребляет столько же» или «не влияет на батарею» без повторяемых измерений. Целевой принцип — отсутствие дополнительной постоянной нагрузки в idle и отсутствие роста realtime CPU/RAM относительно текущего sampler baseline сверх измеренного допуска.

### 9.5 Статус
RESOURCE CONTRACT APPROVED AS DESIGN. Это архитектурное решение, не реализованный SOUND FORGE, не измеренный benchmark и не подтверждение неизменного энергопотребления. Следующий шаг — baseline profiling существующего sampler (idle, 1/16/32/64 voices, streaming/cache pressure, preset load) и затем реализация offline processor с тестами ограничений памяти/потоков.

## 2026-11-12 — SOUND FORGE: оптимизированный простой план реализации

Пользователь запросил максимально творческую оптимизацию задач при простой реализации и минимальном потреблении CPU/RAM/энергии. Этапы: A baseline profiling; B scan+manifest; C verify+SHA-256/dedup; D 2–3 безопасные операции подготовки с A/B; E SFZ/build validation; F atomic package и только затем простая GUI.
