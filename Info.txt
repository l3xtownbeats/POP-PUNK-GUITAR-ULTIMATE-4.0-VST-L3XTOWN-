## 3. Подтверждённая техническая база и риски

Последний углублённый аудит SamplePool/SamplerEngine подтвердил:
- загрузка SFZ строит candidate snapshot и публикует его атомарно после проверки generation token;
- старые snapshots и streaming services удерживаются до уничтожения SamplePool для защиты активных raw pointers;
- текущие ограничения: до 128 snapshots и до 8 streaming library roots на экземпляр;
- SamplerEngine содержит 64 заранее выделенных voice slots;
- cache miss не должен блокировать audio thread; voice удерживает cursor до получения страницы;
- streaming worker дренирует очередь при штатной остановке;
- после исключения worker автоматически не восстанавливается.

Открытые инженерные риски:
1. безопасное освобождение старых snapshots без use-after-free;
2. совокупная память/потоки при нескольких streaming roots;
3. политика восстановления после падения streaming worker;
4. стресс 64 voices при cache pressure, queue overflow и loop prefetch;
5. cancellation/lifetime гонки при загрузке и уничтожении processor;
6. полная Windows Release + CTest + pluginval проверка после изменений.

Нельзя удалять старые snapshots простым сбросом unique_ptr, пока не доказано quiescence всех audio readers.

## 4. Архитектура семейства Guitar / Bass

Принято: один общий низкоуровневый PPGU Audio Engine и два самостоятельных продукта — Guitar Edition и Bass Edition. Общими могут стать streaming, WAV/SFZ reader, cache, queues, state/preset infrastructure, MIDI primitives, FX infrastructure и QA. Guitar/Bass артикуляции, SoundBank, presets, product identity и UI-профили остаются раздельными. Это архитектурное решение, не готовая реализация.

## 2026-11-12 — C1083 / generated BinaryData.h regression fix

**Статус:** SOURCE FIX COMMITTED; WINDOWS BUILD PENDING.  
Source commit: `0ef0ebe934350d57779328a5e0979f1134ae85f2` (parent: `e21980eee5289b00db371b3c2a907a5d0016b19a`).

В `CMakeLists.txt` добавлена отдельная JUCE binary-data цель `PPGUTestData` до создания зависимого integration-test target. Цель использует маленький нейтральный fixture `tests/assets/ppgu_test_data.txt`, namespace `PPGUTestData` и линкуется непосредственно к `ppgu_processor_pattern_tests`. Это обеспечивает generated include directory и `JUCE_TARGET_HAS_BINARY_DATA` для test target в чистом build tree.

**Важное уточнение JUCE API:** в закреплённой проектом JUCE 7.0.12 сигнатуре используется аргумент `NAMESPACE`, а не `HEADER_NAMESPACE`; сгенерированный заголовок по умолчанию называется `BinaryData.h` и попадает в include directory target. Поэтому путь `PPGUTestData/BinaryData.h` из чернового примера REV 13 не используется: JUCE добавляет generated header через `JuceHeader.h` при наличии `JUCE_TARGET_HAS_BINARY_DATA`. Основание: JUCE CMake API и реализация `juce_add_binary_data`.

GitHub Actions run #827 / ID `43113647167` создан на source commit `0ef0ebe934350d57779328a5e0979f1134ae85f2`; на момент записи состояние `queued`. Локальная Windows/MSVC Release-сборка в этой среде не выполнялась. Следовательно, исправление пока **не объявляется BUILT или TESTED**. Следующие гейты: полный build всех targets, CTest, locate VST3, pluginval strictness 5 и packaging.

Отдельное расхождение REV 13 для последующего согласования: текущий root CMake всё ещё закрепляет JUCE 7.0.12 и minimum CMake 3.22; REV 13 §13.2 требует JUCE 8 и CMake >=3.24. Версии не менялись в рамках изолированного C1083 fix, чтобы не смешивать причины сборочных регрессий.
