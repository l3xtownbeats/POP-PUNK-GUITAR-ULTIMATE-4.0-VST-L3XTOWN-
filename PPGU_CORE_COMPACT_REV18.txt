## 1. ПРОДУКТ
C++/JUCE-разработчик + UI-дизайнер. PPGU: Windows x64 VST3-синтезатор
(IS_SYNTH, MIDI input), JUCE 7.0.12 (pin), C++20, FL Studio 20, Win10 x64.
Приоритеты: безопасность → realtime → звук → ресурсы → UX.

## 2. ТЕМА-СТАНДАРТ (BINDING, ВЫШЕ ВСЕХ ДОКУМЕНТОВ)
- Единая тема: NEON STAGE DEFAULT SKIN-1 = skin-053/Skin_053.
  Default при первом запуске, reset target, fallback. Всегда первая.
- «Тема/скин/интерфейс/оболочка» — один объект. SOUND FORGE и SIGNAL
  FORGE как имена тем = NEON STAGE. Отдельных тем не создавать.
- Остальные темы: строго SKIN-2, SKIN-3, SKIN-4… без пропусков/дублей.
- Определение темы (обязательная формулировка): «дефолтная визуальная
  тема интерфейса плагина с использованием минимальных ресурсов CPU RAM».
- Все окна наследуют палитру NEON STAGE через ThemeManager::applyPalette.
- Legacy-имена реестра (Neon Riot и пр.) — только no-loss migration audit,
  не превращать в активные темы. Live-конфликт реестра решает миграция,
  не переименование.

## 12. ЭФФЕКТЫ И АНИМАЦИИ (BINDING)
Блики, отражения, свечения, тени, градиенты, неоновые обводки — без
бандинга, единый источник света. Живые анимации: hot-swap 150 мс, ручки/
слайдеры с бликом и дугой, hover/pressed/focus с easing, key-reactive
подсветка по реальному MIDI-стейту, переходы FX/панелей.
Ограничения: анимировать только реальное состояние (запрещено — A7);
тяжёлый блюр/шейдеры → baked-слои (PNG с альфой), не пересчёт в кадре;
ECO упрощает анимации (reduceInEco); цель 60 FPS, при конфликте —
профилирование. Цвета эффектов = производные canonical tokens, CRC.

## 13. РЕСУРСЫ (BINDING)
ДЕФОЛТ = МИНИМАЛЬНОЕ потребление RAM/CPU/GPU/видеоядра во всех состояниях,
включая простой и свёрнутый редактор. Возможности (GPU-ускорение, HiDPI
100–400%, 4K/8K, мультимонитор, антиалиасинг, atlas, 60 FPS) — только по
реальной необходимости и с минимальными затратами; HiDPI рендерит строго
по реальному масштабу экрана.
CPU: без busy-wait; анимации 30–60 Гц по необходимости; пауза repaint при
неактивности; repaint по областям. GPU: рендер только при изменениях,
статичные слои кэшируются, baked > runtime-шейдеры.
Память: lazy loading, LRU, atlas, без утечек, кэши с лимитом + eviction.
Заявления об эффективности — только с замерами (профилировщик, FPS/RAM/CPU).
Аудиопоток всегда в приоритете: нулевая нагрузка рендерингом, тяжёлое —
вне audio callback.

## 14. РЕЖИМЫ ОТОБРАЖЕНИЯ (BINDING)
«ЭФФЕКТЫ» (полный премиум) и «МИНИМАЛИЗМ» (чистый стандарт, минимум
CPU/RAM). ДЕФОЛТ = МИНИМАЛИЗМ: первый запуск, сброс, fallback.
Переключатель в SETTINGS + SKIN-меню; сохраняется между сессиями; ничего
не переключается самовольно. Минимализм — режим ЕДИНОЙ темы, не другая
тема: палитра/layout/контролы идентичны. Переключение — только флаги
визуального слоя; аудио и APVTS не трогаются. Оба режима проходят одни
и те же проверки.

## 16. ЗВУК / ПРЕСЕТЫ / САМПЛЕР
- READY REV.18: ≥500 MELODY + ≥500 PATTERN (runtime + загрузка + SHA-256
  mapping + performance validity + human listening). CI-артефакты =
  INTERIM-CI-NOT-RELEASE.
- PATTERN = инструкция исполнения, sync с tempo хоста. Fallback §15:
  сборка из one-shots без loop.
- Бюджет движка (не увеличивать без профилирования): ≤128 snapshots,
  ≤8 streaming roots, 256 cache slots/root, 4096 frames/page
  (~8 MiB/root, ≤64 MiB на 8), 64 voice slots. Cache miss не блокирует
  audio thread; сброс snapshots только после quiescence.
- SoundBank: без лимитов размера, SHA-256 гейт по каждому WAV.
- Samples: лимит 25 GB — только для Sound Hunter, НЕ для ручного импорта
  (Import Guitar / Samples → Import Sample Bank); оригиналы не удалять/
  перезаписывать, additive-only в уникальные пути; SHA-256, дедуп,
  лицензии, ANGELA NON-REGRESSION обязательны независимо от лимита.
- Sound Hunter: только REAL_RECORDED гитара; лицензия GREEN = CC0/PD
  allowlist + evidence + APPROVED + SHA-256 + SNR ≥40 dB + no clipping +
  DC ≤0.0001 + GUITAR_CONFIRMED; YELLOW manual-only; RED не override;
  GOLD — human listening; COPYRIGHT SUSPECT блокирует. Travis Barker 82:
  только verified credits, без top-level категории.
- Пресеты: привязка к реальным ассетам с SHA-256; fallback совместимого
  источника; multi-source tone assembly; стандартное VSTi-плейбилити
  (клавиша = своя нота); аудиотабу против «пластикового» звука.

## 17. ГОТОВЫЕ РЕШЕНИЯ И ОПТИМИЗАЦИЯ
Для каждой функции: 1) исследовать аналоги (библиотеки, SDK, движки,
в т.ч. sfizz-класс — исследовать, не интегрировать без аудита лицензии);
2) сравнить по качеству/лицензии/совместимости Win10 x64 VST3 FL20/CPU/RAM;
3) предпочесть интеграцию разработке с нуля; 4) своя реализация — только
если готовое не проходит, и то простейшая; 5) лицензии проверить ДО
интеграции; 6) главный приоритет — низкое CPU/RAM, быстрый старт, малая
задержка; 7) не удалять/ломать утверждённые функции.
Оптимизация — этап реализации, а не «потом»: оценивать пики, в audio
callback — ноль I/O, блокировок и аллокаций; «стало быстрее» — только
с бенчмарком.

## 18. ДИСЦИПЛИНА И СТАТУСЫ
Цикл: CHECK → ANALYZE → IMPLEMENT/FIX → RETEST → REPORT.
Шкала: Implemented / Partial / Unverified / Not implemented / Blocked.
PLANNED≠IMPLEMENTED; COMMITTED≠BUILD VERIFIED; CI PASS только на точном
SHA; DAW≠HOST-VERIFIED без ручной проверки в FL Studio 20.
Изменения исходников → COMMITTED → полный exact-SHA гейт (Release →
CTest → VST3 locate → pluginval 5 → packaging) → запись в Info.txt.
Валидация провалена → чинить причину, не тест. Обход проверок запрещён.
Обратная совместимость APVTS/state/preset обязательна.
Каждый элемент UI = назначение + callback + состояние + tooltip +
accessibility. Ничто не переключается самовольно.
