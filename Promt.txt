==========================================================================
ЧАСТЬ 1. КОНЦЕПЦИЯ
==========================================================================
VST3-инструмент «Pop Punk Guitar» (PPGU) — гитарный сэмплер-ромплер-гибрид:
- Паттерновая секвенция аккордов и фраз (как Session Guitarist), а не набор
  сэмплов одной ноты.
- Пресет = полный снапшот: звук (амп,cab,FX) + стиль игры (Style DNA) +
  привязанные паттерны.
- Три главных функциональных блока в приоритете:
  1. PRESETS — быстрый выбор звука и стиля.
  2. MELODY — живая игра мелодии по клавиатуре (артикуляции, легато, слайды).
  3. PATTERN — автоматическая игра фраз под MIDI-аккорды. КЛЮЧЕВОЙ ПРИНЦИП:
     каждая нота аккорда, сыгранная в MIDI, трактуется как АККОРД — плагин
     сам строит гитарную аппликатуру и играет фразу.
- Хост: FL Studio 20, ОС: Windows 10 1809+ (64 бит), формат: VST3.
- Язык интерфейса: русский.

==========================================================================
ЧАСТЬ 2. СТЭК И ДВИЖОК — РЕШЕНИЕ ФИКСИРОВАНО
==========================================================================
2.1. Решение: собственное ROMpler-ядро в духе reFX Nexus (принципы) на
примитивах JUCE 7. НЕ физмоделирование. НЕ juce::Synthesiser как основа.
Почему Nexus-принципы: фиксированные слои сэмплов (velocity x RR x артикуляция),
потоковое чтение с диска вместо полной загрузки в RAM, пресет как полный
снапшот параметров с мгновенной сменой, фиксированная внутренняя FX-цепочка,
минимум ручек на главном экране.
Сверху — интеллект Session Guitarist: фразы, кейсвитчи, распознавание аккордов.
2.2. Запрещено: сторонние сэмплерные движки, зависимости с лицензиями,
ограничивающими распространение.
2.3. Требования к среде: CMake >= 3.22, MSVC (VS 2022 toolset v143, /std:c++20),
целевая минимальная система Win10 1809 — НЕ использовать API новее.
2.4. ЭТАПЫ СОЗДАНИЯ ДВИЖКА E1–E6 (каждый = критерий приёмки вехи):
  E1. Каркас аудио-графа: processBlock, transport, параметры APVTS.
  E2. Банк-ридер + SampleSource (формат на выбор ИИ — см. Часть 11).
  E3. Идеальная одна нота: атака, релиз, отсутствие кликов, RR.
  E4. VoiceManager: полифония, политика кражи голоса, доигрывание release.
  E5. PatternScheduler + AutoChords + генератор аппликатуры.
  E6. StyleEngine + FXRack.
  ЗАПРЕЩЕНО начинать GUI до завершения E6.

==========================================================================
ЧАСТЬ 3. ПРОИЗВОДИТЕЛЬНОСТЬ — БЮДЖЕТЫ (ИЗМЕРИМЫЕ)
==========================================================================
- Нагрузка CPU при 64-сэмпловом буфере, 48 кГц: <= 10% на Intel i5 2 ядра.
- RAM в покое (плагин загружен, без активного пресета/воспроизведения): целевой диапазон 50–150 МБ; при загруженном пресете и используемых им сэмплах: ориентир 400–700 МБ. Это целевые бюджеты, а не повод ухудшать качество; меньше — лучше, если не страдают звук, стабильность, скорость загрузки и отсутствие dropout. Верхняя защитная граница рабочего набора — 1.5 ГБ независимо от общего размера библиотеки.
- Старт плагина (от загрузки в FL до готовности): <= 2 с на HDD.
- Смена пресета: <= 10 мс, без кликов, без обрыва релизов (см. 4.4).
- Задержка MIDI: не больше, чем буфер хоста.
- Dropout'ы: 0 при буфере 64 сэмпла на тестовом рендере 60 с (см. Часть 24).

==========================================================================
ЧАСТЬ 4. АРХИТЕКТУРА ЯДРА (ТРИ ПОТОКА + REF-COUNT)
==========================================================================
4.1. Аудио-поток: только DSP, никаких аллокаций, блокировок, файлового IO.
4.2. Сообщение-поток: GUI <-> параметры (AtomicValue, FIFO).
4.3. Фоновый поток: загрузка/распаковка сэмплов, сканирование библиотек.
Приоритет ниже аудио-потока.
4.4. ПРЕСЕТ-СНАПШОТ И REF-COUNT: при смене пресета активные голоса удерживают
ссылку (shared_ptr) на старый снапшот и ДОИГРЫВАЮТ release-хвосты до конца.
Новый снапшот подхватывают новые голоса. Это устраняет обрыв хвостов при смене.
4.5. PatternScheduler: горизонт планирования = max(bufferSize, 512) сэмплов.
Позиция в такте из PPQ хоста с поправкой на sampleOffset события. План блока —
отсортированный список (offset, voiceCommand). НЕ перебор голосов.
4.6. Смена паттерна — квантованная по ближайшей 1/16 (или 1/32 — параметр).
4.7. Внутренний тактовщик: источники времени — PlayHead хоста; при офлайн-рендере
без PlayHead — fallback на внутренний BPM из параметра.
4.8. Обработка смены размера буфера хостом на лету — обязательна.
4.9. MIDI panic: All Notes Off => контролируемый fade-out всех голосов 30 мс.
4.10. PreviewBus: демо-фраза и предпрослушивание паттерна рендерятся в
отдельный lock-free кольцевой буфер — превью не трогает основной транспорт.

ЧАСТЬ 6. БИБЛИОТЕКА ЗВУКОВ — СОСТАВ ПО СТИЛЯМ ГРУПП (ЗВУКОВЫЕ РЕФЕРЕНСЫ)
==========================================================================
6.0. Юридическая рамка: все сэмплы и пресеты — собственные реконструкции
жанра pop-punk. Названия групп — только ориентир стиля (тембр, строй, приём).
Сэмплы НЕ берутся из записей этих групп.

6.1. Состав библиотеки (минимум для вехи M5):
- Гитара 1: мощная «поп-панк» электрогитара с одиночной катушкой моста
  (мостовой хамбакер для чистых партий) — базовая для большинства стилей.
- Гитара 2: альтернативная с более тёмным/плотным тембром (для «модерн»-групп).
- Акустика: для балладных и «жанровых» пресетов (Yellowcard-стиль слоёв).
- Артикуляции на каждую: open chord hits, muted chugs, palm-mute 8th,
  palm-mute 16th, power chord sustains, single note runs, slides, harmonics
  (flageolet), tremolo, skank (upstroke), hammer-on/pull-off samples,
  fret noise, release-сэмплы на каждую струну и каждое состояние мьюта.
- Диапазон: струны 1–6, E2–C6+. Velocity-слои: 5. RR: минимум 3,
  вариации НЕ повторяются дважды подряд (RR-счётчик с запретом повтора).
6.2. Дабл-трек: DoubleProcessor с фазовой совместимостью дублей; HPF 200 Гц
на одном из дублей для предотвращения фазовой провалки низа.
6.3. Тюнинг стилей: пресеты распределены по строям (см. Часть 7):
E standard, Eb (полутон ниже), Drop D, Drop Db — банк обязан содержать
сэмплы или корректный транспон-кэш для каждого строя.

ЧАСТЬ 7. ПРЕСЕТЫ — НЕ МЕНЕЕ 300, РАСПРЕДЕЛЕНИЕ ПО СТИЛЯМ ГРУПП

7.3. РАСПРЕДЕЛЕНИЕ ПО ЗВУЧАНИЮ (референсы стиля, НЕ копии контента групп):

ГРУППА B — «МОДЕРН-ТОЛСТЫЙ ПОП-ПАНК» (денсированный, многослойный, чаще Eb/

Good Charlotte, Bowling for Soup, Simple Plan. Пресеты: 7 групп уровня 1.

ГРУППА C — «ЭМО/ТЕМНЫЙ ПОП-ПАНК» (резкие стаккато-риффы на пауэр-кордах,

Ключевые черты: быстрый стаккато palm-mute с октоавными ходами, узкий

ГРУППА D — «МЕЛОДИЧНЫЙ/АКУСТИЧЕСКИЙ ПОП-ПАНК» (чистые гитары, delay, открытые

Пресет наследует DNA от своей группы. Пользователь может править DNA —

7.5. ПРЕСЕТ «PHOTOGRAPHS» (Mest — жанровая реконструкция) — обязателен в

7.6. Каждая группа имеет: демо-фразу (короткий аудио-кусочек, рендерится

==========================================================================
ЧАСТЬ 8. РЕЖИМ MELODY (МЕХАНИКА КАК У SESSION GUITARIST ESD)
==========================================================================
8.1. Кейсвитчи артикуляций C1–D#1: Open, Muted (palm-mute), Flageolet
(гармоники), Tremolo. Выбор медиатор/пальцы для каждой артикуляции —
отдельные слоты атаки в банке.
8.2. Монофонический режим: одиночная мелодия, однолосный легато-движок
для соло и басовых линий.
8.3. Автоматические hammer-on/pull-off: подставляются при смене высоты на
той же струне или заметном изменении velocity; при смене аккордов
автоматически добавляется шум ладов (fret noise).
8.4. Слайды: B1 — модификатор (нота начинается со слайда вверх/вниз
в зависимости от предыдущей). Скорость слайда от velocity. В арпеджио слайд
срабатывает при velocity > 110.
8.5. Питч-бенд с типами: All / Lowest / Highest / Softest / Loudest / Latest —
гнётся только выбранная нота, остальные струны (например, открытые) держат
высоту.
8.6. Мод-вил = вибрато. Лимит паттерн-слотов в Melody: 4.
8.7. Двустороннее совмещение: удержание кейсвитча паттерна E1–G1 левой рукой
временно играет паттерн, пока правая играет мелодию — и из Pattern
аналогично временно включается мелодия.
8.8. Прослушивание пресета: выбор пресета в Melody => демо-фраза звучит
ОДИН РАЗ (без лупа).

==========================================================================
ЧАСТЬ 9. РЕЖИМ PATTERN (МЕХАНИКА КАК У SESSION GUITARIST ESD)
==========================================================================
9.1. Паттерн = записанная фраза исполнения (1, 2 или 4 такта), синхронизируемая
к темпу хоста, с сохранённым «человеческим» таймингом.
9.2. 8 слотов паттернов на кейсвитчах E1–G1, привязка фраз к пресету
(Song-подход ESD: пресет = звук + до 8 связанных паттернов).
9.3. Распознавание аккордов со слэшами (C/E, Dmi7/F, Ami/E) и генератор
аппликатуры: тона аккорда раскладываются по струнам на реальные лады —
НЕ буквальные высоты.
9.4. Кейсвитчи концовок G#1/A1/Bb1: три длины концовок (с возможностью
сменить аккорд перед нажатием), слайд B1, удар ладонью, шлепок по струнам.
9.5. Страница Playback: Swing (база 8th/16th), Humanize (0% = полная
квантизация, 100% = оригинал записи), Accent вместо входного velocity —
фразы его игнорируют.
9.6. Start on first chord: фраза стартует с первого аккорда с начала такта,
игнорируя позицию хоста. Плюс sync-режимы и глобальный offset через CC#111
для нестандартных размеров.
9.7. Временный Pattern из Melody: удержание кейсвитча E1–G1 переключает
режим, отпускание — возврат с доигрыванием «ещё одной ноты на сильную долю».
9.8. Rhythm Search в браузере паттернов — поиск фраз по ритмическому рисунку.
9.9. Прослушивание паттерна: нажатие стиля в Pattern => ОДИН такт
предпрослушивания (не луп).
9.10. Фразы хранятся как событийные данные (НЕ аудио-лупы) — транспонируются
любым аккордом и перекрашиваются Style DNA.
9.11. ПРИНЦИП «КАЖДАЯ НОТА = АККОРД»: во вводе MIDI одиночная нота трактуется
как корень аккорда — плагин достраивает трезвучие по гармонии фразы.

10.1. Окно FX EDIT: 7 эффектов в фиксированных слотах — Compressor, EQ,

10.2. Drag-and-drop ПОРЯДКА эффектов в цепочке.

==========================================================================
ЧАСТЬ 11. ФОРМАТ БИБЛИОТЕКИ — НА ВЫБОР ИИ
==========================================================================
11.1. Формат НЕ навязан. ИИ выбирает сам: упакованный .ppgb (манифест +
zstd) ИЛИ папку WAV-сэмплов с JSON/XML-манифестом — и ОБЯЗАН обосновать

11.2. Допустимо поддержать ОБА формата: WAV — удобство редактирования и
дополнения, .ppgb — компактность и быстрый поток.
11.3. Единый интерфейс SampleSource: аудиодвижок не знает, откуда пришли
сэмплы. Смена формата не меняет код звука.
11.4. МАКСИМАЛЬНОЕ КАЧЕСТВО СЭМПЛОВ (обязательные требования):
- Предпочтительный исходный мастер: lossless PCM WAV 24 бит / 48 кГц или
  выше. Пользователь может импортировать аудио из распространённых форматов:
  WAV, AIFF, FLAC, OGG Vorbis, MP3, AAC/M4A и других форматов, для которых
  подключён и проверен декодер. Архитектура декодеров расширяемая; неизвестный
  или неподдерживаемый формат должен давать понятную ошибку, а не падение.
- Импорт выполняется в фоне: декодирование -> внутренний lossless формат
  Sample Bank (PCM float с исходной частотой/каналами либо lossless PCM после
  качественного ресемплинга по правилам формата банка) -> проверка целостности
  и запись манифеста. Внутри .ppgb не применять повторное lossy-кодирование;
  исходный файл пользователя по умолчанию не изменять.
- Lossy-источники (MP3/AAC/OGG) разрешены как вход для импорта, но декодирование
  не восстанавливает потерянную информацию исходника. После импорта не
  добавлять новых потерь: хранить внутреннее представление lossless. Для
  максимального качества рекомендовать lossless-мастера.
- Поддерживать batch import, определение формата по содержимому, валидацию
  sample rate/каналов/длительности, корректную обработку повреждённых файлов,
  прогресс/отмену, журнал импорта и сохранение метаданных.
- Запись собственных исходников: без компрессии и лимитера на дорожках
  (обработку делает плагин), уровень с запасом до -6 дБ, единый шум и
  тональный баланс между слоями.
- Содержимое фабричной библиотеки: 6 струн, E2–C6+, 5 velocity-слоёв,
  минимум 3 RR, отдельные release-сэмплы для каждой струны и мьют-состояния.
- Хвосты: полные естественные затухания без обрезки с щелчком; луп только
  для чистых тонов с точкой на нулевой фазе.
- Фазовая совместимость дублей.
- Движок не портит качество: Hermite-ресемплинг, oversampling 2x у
  дисторшна, никаких линейных удешевлений.
- Приоритет: качество важнее веса библиотеки — ограничений по размеру НЕТ.
11.5. Пользовательские библиотеки: установка в %APPDATA%/PPGU/Libraries,
фабричные библиотеки защищены от перезаписи. Импортированные библиотеки
индексируются и загружаются лениво: при выборе пресета в cache попадают
только его необходимые assets.

### M2 — обязательные требования к prefetch и совместному доступу к страницам (уточнение 10.11.2026)
- Prefetch должен выполняться только worker-потоком по bounded request queue; audio thread только отправляет фиксированный запрос и никогда не ждёт его выполнения.
- При note-on запрашивать первую страницу sample; заранее подготавливать следующую страницу по lookahead, достаточному для текущей скорости воспроизведения и размера аудиоблока. Для loop regions заранее держать loop-start/loop-continuation pages.
- При нехватке cache слотов/очереди не блокировать audio thread: фиксировать miss/underrun telemetry, продолжать безопасным fallback без чтения неготовой памяти. Повторный запрос должен быть коалесцирован, чтобы несколько голосов не создавали одинаковые disk reads.
- Одна immutable page должна быть доступна нескольким голосам одновременно через отдельные read leases. Eviction разрешён только когда число leases равно нулю; worker не может менять данные опубликованной страницы.
- Regression/stress acceptance: несколько параллельных reader threads читают одну страницу, worker одновременно пытается вытеснять/перезаполнять cache; ни одного повреждённого значения, use-after-free или блокировки audio-side API. Допускаются cache misses, но не повреждение данных и не blocking.
- Host acceptance: 100 последовательных/параллельных note hits и переключения buffer size без clicks/dropouts; измерить cache hit/miss, prefetch hit, queue overflow, decode latency.
- Эти требования дополняют, но не заменяют интеграцию WavPageReader/PageCacheSlots в реальный voice playback path.
