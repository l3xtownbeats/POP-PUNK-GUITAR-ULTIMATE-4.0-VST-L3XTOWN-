# GRAPHIC SKIN — REV.19

## Утверждённая архитектура

- **SIGNAL FORGE = CONTROL DECK** — единая функциональная основа плагина.
- **NEON STAGE** — готовый эталон GRAPHIC SKIN. Его реализацию переносим в REV.19 выборочно, с проверкой совместимости; повторная разработка эталона не требуется.
- Итог продукта — ровно **16 полноценных рабочих GRAPHIC SKINS**.
- Каждый скин обязан визуально отражать каждый существующий элемент CONTROL DECK: панели, кнопки, регуляторы, переключатели, индикаторы и окна.
- Все 16 скинов имеют одинаковые функции, состояния и привязки. Переключение меняет только оформление.
- Сохраняются все контракты REV.19: 27 пользовательских контролов, семь утверждённых FX bypass IDs, APVTS IDs, MIDI, аудио, DSP и существующие функции.
- Нельзя придумывать контролы, функции, APVTS ID или выдавать макет за работающий элемент.

## Текущий статус реализации

- SKIN-1 NEON STAGE — готовый графический эталон; перенос и проверка совместимости в REV.19 выполняются отдельно.
- SKIN-2…SKIN-16 — утверждённые темы проекта. Их статус реализации определяется фактическими artwork/assets, паритетом CONTROL DECK и runtime-проверками.
- В активный runtime registry допускаются только темы, прошедшие обязательные проверки. Наличие записи в последовательности не означает готовность или доступность в плагине.
- Набор каталогов проекта ограничен указанными 16 темами. Неиспользуемые темы и материалы вне этого набора не являются частью разработки, сборки или отчётности.

## Обязательные критерии приёмки каждой темы

1. Полное визуальное соответствие SIGNAL FORGE (CONTROL DECK).
2. Отображение всех существующих панелей, кнопок, регуляторов, переключателей, индикаторов и окон.
3. Совпадение поведения и состояний с функциональной основой.
4. Проверка artwork, PNG/SVG, путей и целостности ресурсов.
5. Проверка читаемости, контрастности, масштаба и адаптации интерфейса.
6. Runtime-проверка переключения темы и отсутствия регрессий.
7. Точная Windows x64/VST3 сборка, CTest и pluginval Strictness 5; host acceptance в FL Studio 20 фиксируется отдельно.

## Правило переноса NEON STAGE

Переносить в REV.19 только проверенные компоненты, стили, ресурсы и логику отображения. Перед каждым переносом анализировать diff, зависимости и совместимость с REV.19. Слепое слияние запрещено. Существующие функции и контракты REV.19 сохраняются.
