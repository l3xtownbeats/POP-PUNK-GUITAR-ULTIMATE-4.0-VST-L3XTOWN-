# PPGU — руководство по темам и пользовательским скинам

**Документ:** пользовательская и дизайнерская инструкция  
**Продукт:** POP PUNK GUITAR ULTIMATE (PPGU), Windows x64, VST3  
**Статус функции на момент документа:** SPECIFIED / PARTIALLY SCAFFOLDED / NOT RUNTIME-INTEGRATED

> Важно: это руководство описывает целевое поведение и текущий формат авторинга. Оно не означает, что Theme Gallery, live switching или установка пользовательских тем уже доступны в собранном плагине. В текущем main ThemeManager частичный и не подключён к PluginEditor. До прохождения критериев приёмки ниже функция не должна рекламироваться как готовая.

## 1. Что такое тема PPGU

Тема (skin) задаёт только визуальное оформление интерфейса. Целевой охват тематизации:

- фон окна, поверхности и панели секций;
- визуальный стиль rotary controls, sliders и кнопок;
- tabs, combo boxes, keyboard и визуальные индикаторы;
- текст, подписи, readouts, рамки, фокус и состояния контролов;
- декоративные материалы, фоновые изображения и дополнительные графические слои — если соответствующие assets поддержаны runtime.

Тема **не должна** менять звук, APVTS-параметры, MIDI, пресеты, MELODY/PATTERN, маршрутизацию, аудиодвижок, размеры/расположение контролов или их hit areas. Тема не может добавлять функции, которых нет в реальном интерфейсе.

### Текущий каталог — без завышения количества

В репозитории объявлено **50 канонических слотов**: `skin-01` … `skin-50`. Реестр `theme_manifest.json` указывает `skin-01` как default. В исходном дереве также обнаружен `Skin_51`, но он не входит в schema/registry и не является принятым слотом.

Заявление «61 готовая тема: шесть семейств по десять плюс default» не соответствует текущему каталогу и не используется в этом руководстве. Текущий registry группирует темы по кластерам A/B/C; это не шесть семейств `studio_dark / hardware_light / neon / vintage / chrome / wood`. Не считайте такие семейства или 61 тему существующим каталогом до отдельной нормализации и проверки.

Файлы в `SKIN/Skin_XX/` сейчас содержат манифесты `theme.json`. Наличие записи `assets/preview.png`, `assets/hero.webp` или `assets/texture.png` в манифесте не означает, что файл уже существует. Графические файлы, полноценные SVG/control artwork и runtime-галерея ещё не приняты.

## 2. Где хранятся темы

### Исходники разработчика

В репозитории используется каталог:

```text
SKIN/
├── theme.schema.json
├── theme_manifest.json
├── Skin_01/
│   └── theme.json
├── Skin_02/
│   └── theme.json
└── ...
```

Это **каталог исходников**, а не runtime-папка установленного продукта.

### Целевая структура установленного продукта

Единственный согласованный основной runtime-путь — папка **`Skins` непосредственно рядом с установленным VST3 bundle**:

```text
VST3 install directory/
├── POP PUNK GUITAR ULTIMATE.vst3/
└── Skins/
    ├── skin-01/
    │   └── theme.json
    ├── skin-02/
    │   └── theme.json
    └── ...
```

Windows VST3 bundle сам является каталогом. Runtime должен определить фактический путь установленного bundle и найти соседнюю `Skins/`; нельзя полагаться на current working directory DAW. В качестве основного расположения не использовать `%APPDATA%\PPGU\themes`, Documents или отдельную системную папку. Не создавать альтернативный путь незаметно.

Инсталлятор/пакет должен создать sibling `Skins/` заранее. Если каталог находится в Program Files и недоступен для записи обычному пользователю, добавление или обновление тем выполняется установщиком либо пользователем с необходимыми правами. Плагин не должен пытаться обходить права Windows.

> На текущем этапе это целевой контракт поставки. Текущий workflow включает manifests в ZIP как `SKINS/`, но установка sibling-папки и runtime discovery ещё не подтверждены.

## 3. Смена темы в интерфейсе

Целевой пользовательский сценарий после реализации:

1. Открыть окно PPGU в DAW.
2. Нажать `SKIN` и открыть Theme Gallery.
3. Найти тему через список/поиск и просмотреть доступную карточку preview.
4. Выбрать тему.
5. Плагин применяет её без изменения звукового состояния; выбранный ID сохраняется отдельно от preset/APVTS state.

Планируемые возможности Gallery: категории/кластеры, поиск, избранное, preview, клавиатурная навигация и возврат к default. Плавный переход около 150 мс — целевое UX-требование, а не подтверждённая функция. До runtime-интеграции нельзя обещать мгновенное переключение, отсутствие перезапуска окна или восстановление темы в следующей сессии.

## 4. Как создать пользовательскую тему

### Шаг 1. Подготовьте копию существующего манифеста

Используйте один из принятых манифестов `SKIN/Skin_01/theme.json` … `Skin_50/theme.json` как отправную точку. Создайте отдельную папку с уникальным ID. Не редактируйте встроенный слот напрямую, если хотите сохранить исходную тему.

Целевой пакет темы:

```text
my-custom-skin/
├── theme.json
├── assets/       # preview/hero/texture, только если предусмотрены спецификацией
├── svg/          # только поддержанные runtime SVG layers
├── textures/     # дополнительные растровые текстуры
├── icons/        # опционально, если формат поддержан
└── fonts/        # опционально, с проверкой лицензии и runtime support
```

Наличие папок `svg/`, `textures/`, `icons/` или `fonts/` само по себе не гарантирует, что текущий плагин их загружает. Не добавляйте произвольные поля и не рассчитывайте, что runtime их применит.

### Шаг 2. Редактируйте theme.json по реальной схеме

Главный контракт — `SKIN/theme.schema.json` (JSON Schema 2020-12). Текущая схема требует, среди прочего:

- `schemaVersion` со значением `1.0.0`;
- `id` формата `skin-NN` и `index` от 1 до 50 для встроенного каталога;
- `name`, `description`, `cluster` (A/B/C), `identity`;
- `tokens` с 18 группами визуальных токенов;
- `assets`, `assetSpec`, `compatibility`, `validation`.

Используйте имена полей и вложенную структуру непосредственно из действующего `theme.schema.json` и проверенного манифеста. Не заменяйте эту структуру упрощённым объектом с `family` и `palette`: такой формат не соответствует текущей схеме. Для сторонней темы не занимайте ID встроенного слота; окончательная политика внешних ID/папок должна быть закреплена в runtime schema до объявления пользовательских пакетов совместимыми.

Все цветовые значения должны соответствовать формату `#RRGGBB`, если schema требует цвет. Сохраняйте полный набор обязательных token groups. Не удаляйте обязательные поля, не меняйте APVTS IDs и не помещайте в манифест исполняемый код.

### Шаг 3. Подготовьте графику

Перед добавлением assets:

- проверьте точные размеры и форматы, указанные в `assetSpec`;
- убедитесь, что файлы действительно находятся по относительным путям из `theme.json`;
- проверьте декодирование, прозрачность, масштабирование и читаемость;
- используйте оригинальные изображения и графику, на которые у вас есть права;
- не включайте логотипы, фотографии, шрифты или материалы сторонних брендов без разрешения;
- для шрифтов проверьте право на распространение внутри плагина.

Текстуры должны быть необязательными, если schema/asset contract явно не делает их обязательными. Отсутствующие preview/hero должны диагностироваться; нельзя считать тему полностью готовой, если манифест ссылается на отсутствующие обязательные файлы.

### Шаг 4. Проверьте тему

Перед отправкой пакета проверьте:

1. JSON корректен и проходит `SKIN/theme.schema.json`.
2. ID, index, registry и папка не конфликтуют с другими темами.
3. Все объявленные обязательные assets существуют и открываются.
4. Текст читаем на всех поверхностях; проверьте состояния normal/hover/pressed/disabled/focus.
5. Цветовой контраст приемлем; тема не скрывает значения и индикаторы.
6. Оформление не требует изменения размеров, расположения или hit areas контролов.
7. Нет абсолютных путей, `..` traversal, исполняемых файлов или сетевых зависимостей.
8. Права на все включённые assets документированы.

Текущие проверки в репозитории не покрывают полностью runtime assets, все состояния, DPI, безопасность путей и память. Успешная проверка JSON сама по себе не является подтверждением совместимости с плагином.

## 5. Безопасность и отказоустойчивость — требования к runtime

После реализации движок должен:

- проверять обязательные поля, schema/version compatibility и относительные пути;
- запрещать выход за пределы sibling `Skins/` (path traversal);
- ограничивать размеры/размерности изображений и безопасно обрабатывать ошибки декодирования;
- изолировать повреждённую или несовместимую тему, не допуская падения плагина;
- переключаться на встроенный DEFAULT и показывать понятное предупреждение, например: «Тема <имя> несовместима»;
- записывать диагностическую причину, не раскрывая лишние системные пути;
- загружать растровые ресурсы по требованию с ограничением памяти и LRU eviction;
- в ECO-режиме отключать необязательные анимации, если тема объявляет `reduceInEco` и runtime поддерживает это поле;
- выполнять сканирование/декодирование вне audio callback.

Это требования к проектированию, а не список уже реализованных функций. В текущем main не подтверждены runtime scan, LRU, ECO behavior, полная проверка assets или UI fallback.

## 6. Что тема не может менять

Запрещено менять или подменять:

- звук, DSP, sampler, sample maps и audio routing;
- значения APVTS, preset contents, MIDI mapping и voice behavior;
- логику MELODY/PATTERN, transport или automation;
- control IDs, attachments, hit areas, focus order и layout;
- доступность и смысл кнопок/индикаторов.

Тема меняет только внешний вид уже существующих элементов. Если элемент отсутствует в текущем UI, его нельзя объявлять реализованным только потому, что в дизайне есть графика для него.

## 7. Текущий статус и критерии готовности

Текущий подтверждённый статус:

**SPECIFIED / PARTIALLY SCAFFOLDED / NOT RUNTIME-INTEGRATED.**

В репозитории есть schema, registry, манифесты и частичный ThemeManager. ThemeManager не подключён к PluginEditor; галерея и пользовательская смена темы не приняты; preview/hero/texture и полноценные control assets не подтверждены как присутствующие; в каталоге есть orphan `Skin_51`; пакетная установка sibling `Skins/` не проверена.

Skin Engine можно объявить готовым только после подтверждения всех пунктов:

- канонический каталог и registry согласованы;
- sibling `Skins/` устанавливается рядом с VST3 и runtime безопасно сканирует его;
- Gallery, preview, поиск, выбор, default, keyboard navigation и сохранение preference работают;
- темы применяются ко всем существующим UI controls без изменения layout/APVTS/audio;
- assets существуют, проверяются и безопасно загружаются;
- invalid/missing/incompatible themes корректно откатываются на default;
- проверены hot-swap, отсутствие влияния на аудио, память/LRU, ECO, DPI и accessibility;
- Windows x64 Release, CTest и pluginval проходят;
- выполнена ручная host-проверка в FL Studio 20.

## 8. Файлы проекта

- `SKIN/theme.schema.json` — машинная схема манифеста.
- `SKIN/theme_manifest.json` — реестр встроенных тем.
- `SKIN/Skin_XX/theme.json` — манифест конкретной темы.
- `SKIN/ASSET_SPECIFICATIONS_RU.md` — требования к графическим ресурсам.
- `SKIN/CONTROL_INVENTORY_MATRIX_RU.md` — инвентаризация UI-контролов.
- `SKIN/SKIN_ENGINE_GAP_AUDIT_RU.md` — аудит незакрытых пробелов.
- `SKIN/README.md` — краткий статус и runtime path contract.
- `Info.txt` — единственный журнал разработки проекта.
