## 10 ноября 2026 — полный аудит M1–M3 и исправление sample-accurate offset

Проверена рабочая ветка `migration/full-copy-m3-transport-scheduler-v2`, исходный HEAD `3fc5832f471815e375e10c13f3572d53561fc13b`, спецификация `Promt.txt v33 FINAL`, processor, sampler, scheduler, CMake/CTest и Windows Actions run `42769587683`.

### Подтверждённый результат CI до исправления
- Windows Release compilation и создание VST3 bundle прошли до шага CTest.
- CTest: 5 из 6 тестов Passed; `ppgu_pattern_scheduler_tests` Failed. Run conclusion: `failure`.
- Ошибка локализована статически в тесте near-tail: PPQ 0.00265 при 48 kHz / 120 BPM соответствует sample 63.6. Код преобразовывал double в int усечением (63), хотя контракт требует первый sample НЕ раньше события (64). Ожидание теста 63 было неверным.

### Изменения исходника в этом коммите
- `Source/Performance/PatternScheduler.h`: sample offset теперь рассчитывается через `ceil(exactOffset - 1e-9)`, чтобы не запускать событие раньше его дробной sample-позиции и не сдвигать целочисленные позиции на один sample вперёд из-за погрешности float.
- `tests/PatternSchedulerTests.cpp`: near-tail regression ожидает sample 64; добавлен тест точного целого sample 60, который защищает от лишнего смещения.

### Полный аудит M1
- APVTS state сериализуется и восстанавливается через JUCE XML; базовая параметрическая сериализация присутствует.
- Критический пробел: путь/ID активной SFZ-библиотеки не включён в сериализуемое состояние. При повторном открытии проекта нельзя гарантировать восстановление выбранной библиотеки.
- Не найдены подтверждённые тесты round-trip state, сохранения automation/parameter IDs в DAW, восстановления банка, host panic и смены пресета во время release-tail.
- Pluginval и ручной acceptance во FL Studio 20 для текущего HEAD не подтверждены. M1 остаётся PARTIAL / NOT ACCEPTED.

### Полный аудит M2
- SFZ parser, WAV decode, key/velocity/channel zones, loop metadata, bounded voices и отдельные metadata/page-cache компоненты присутствуют.
- Критический архитектурный разрыв: `SamplePool::loadSfz` декодирует целые WAV в `juce::AudioBuffer` и хранит их в `sampleStorage`; есть лимит 1 GiB и 128 snapshots, после достижения которых загрузка блокируется до перезапуска. Это не streaming/lazy paging по требованию v33.
- `WavPageReader`, `SampleMetadataIndex` и `PageCacheSlots` существуют как отдельные модули, но текущий `SamplerEngine::Voice` читает полные `AudioBuffer`; интеграция page cache в voice playback не подтверждена.
- Round-robin выбор и velocity crossfade в runtime не подтверждены; `findRegion` возвращает первый совпавший регион. Нет доказательства длительного stress/100-hit no-click, unload/reload и memory ceiling на целевой машине. M2 остаётся PARTIAL / NOT ACCEPTED.

### Полный аудит M3
- Scheduler подключён к `processBlock` и dispatch'ит NoteOn/NoteOff в SamplerEngine; MIDI sample positions частично учитываются.
- Подтверждён дефект fractional sample mapping, исправление внесено выше.
- Дополнительные найденные риски для следующих циклов: несколько смен аккорда внутри одного блока схлопываются в один финальный chord snapshot; pattern generation и scheduler имеют фиксированный лимит 512 событий, при заполнении часть событий может быть отброшена без явного overflow report; runtime-тестов полного маршрута MIDI → chord state → scheduler → sampler нет.
- Stop/seek/clock handoff и quantize имеют unit coverage, но полный CTest текущей серии провалился, DAW validation отсутствует. M3 остаётся NOT ACCEPTED.

- M2-003: нет подтверждённого round-robin и velocity crossfade в runtime.
