## 1. Назначение и целевая платформа

Согласован независимый сэмплерный VST-инструмент электрогитары и акустической гитары для поп-панка и смежных стилей.

- Формат выпуска: **VST3 x64**.
- ОС: Windows 10 x64 (целевая минимальная версия — Windows 10 1809) и новее.
- Основная DAW для обязательной проверки: **FL Studio 20 x64**.
- Технологическая база проекта: JUCE 7.0.12, C++20, Visual Studio 2022 / MSVC v143.
- Приоритет: быстрое открытие, быстрая загрузка пресетов, немедленная реакция на MIDI и контролируемая нагрузка CPU/RAM.
- Ориентиры по удобству: FLEX и Session Guitarist; по библиотечной модели — Kontakt. Это ориентиры пользовательского сценария, а не разрешение копировать код, интерфейс, фирменные сэмплы или коммерческие пресеты.

## 2. Два основных режима игры

### MELODY — клавиша = отдельная нота

- Каждая MIDI-клавиша должна играть соответствующую ноту гитары, а не запускать готовую фразу.
- Полноценные мультисэмплы по диапазону грифа с корректными root key и диапазонами клавиш.
- Электрические и акустические тембры.
- Velocity layers, round robin при наличии дублей, открытая нота, palm mute и другие артикуляции — только если они реально размечены в библиотеке.
- Legato, slide, hammer-on и pull-off должны использовать подходящие записи/зоны; нельзя имитировать наличие артикуляции одним названием пресета.
- Velocity должен управлять динамикой и, по согласованному требованию, иметь возможность переключать palm mute по настраиваемому порогу.
- Поддержка Note On/Off, MIDI channel, pitch bend/modulation и перекрывающихся нот с корректным завершением голосов.
- Настраиваемая полифония/voices и предсказуемое voice stealing без щелчков.

### PATTERN — клавиша = аккорд и гитарное исполнение

- Клавиши выбирают аккорды/voicings согласно карте выбранного пресета.
- После выбора аккорда движок исполняет ритмический рисунок, а не просто удерживает один синтезированный аккорд.
- Поддерживаемые музыкальные типы: down/up strums, alternate down-up, palm-muted ритмы, power-chord риффы, chugs, dead/muted удары, арпеджио, picking, акустический strumming.
- Реакция на смену аккорда без зависших нот и с корректным таймингом.
- Host tempo/transport sync, запуск/остановка, смена аккордов, human timing, акценты и gate.
- Для реалистичного PATTERN требуются подходящие chord/strum/performance-записи или подробно размеченные performance events. Одиночные ноты сами по себе не заменяют записи аккордовых исполнений.

## 3. Импорт звуков и форматы

### Поддерживаемые входные аудиоформаты импортёра

Текущая реализация импортёра использует JUCE AudioFormatManager с базовыми декодерами. В коде явно перечислены следующие поддерживаемые форматы:

| Формат | Расширение | Поведение |
|---|---|---|
| WAV | `.wav` | Декодируется и импортируется |
| AIFF | `.aiff` | Декодируется и импортируется |
| AIF | `.aif` | Декодируется и импортируется |
| FLAC | `.flac` | Декодируется и импортируется |
| OGG Vorbis | `.ogg` | Декодируется и импортируется |
| MP3 | `.mp3` | Декодируется и импортируется |
| Native Instruments NCW | `.ncw` | Не поддерживается; файл пропускается с предупреждением |

Фактическая доступность декодера зависит от конфигурации сборки JUCE. Импортёр не должен молча заявлять поддержку формата, если соответствующий decoder отсутствует: такой файл пропускается и попадает в отчёт как неподдерживаемый/нечитаемый.

### Внутреннее представление после импорта

- Аудио приводится к **WAV IEEE Float 32-bit**.
- Исходная частота дискретизации сохраняется; принудительного общего sample rate в описанном конвертере нет.
- Конвертация выполняется блоками, а не чтением всего исходного файла одним массивом.
- Исходные файлы пользователя не перезаписываются.
- Внутри импортированной библиотеки формируется каталог `samples/`, файл `manifest.json` и, если удалось автоматически сопоставить хотя бы один файл, `Imported_Instrument.sfz`.
- В manifest записываются исходный и преобразованный относительные пути, режим/подсказка классификации, root key и размеры файлов.
- Импортёр имеет защитный лимит в 4096 файлов на одну операцию импорта.
- Символические ссылки и пути за пределами выбранного каталога не должны приводить к импорту внешних файлов.
- Импорт выполняется через отдельную staging-папку; опубликование библиотеки завершается атомарным перемещением в конечный каталог.
- Если root note не удалось определить по имени файла, файл всё равно импортируется, но отмечается как **Needs Mapping**. Нельзя угадывать ноту, отбрасывать файл или подставлять произвольный root key.

### Автоматическое сопоставление и SFZ

- Импортёр пытается извлечь MIDI root key из имени файла.
- Если root key найден, создаётся SFZ region с sample, key, lokey и hikey, равными найденной ноте.
- Если root key отсутствует, запись остаётся в manifest для ручного сопоставления; такой файл не считается автоматически готовой playable zone.
- Генерируемый SFZ использует относительные пути внутри импортированной библиотеки.
- После атомарной публикации путь к SFZ должен ссылаться на конечную папку, а не на временный staging-каталог. Исправление этого пути зафиксировано в commit `39626076a8ded975bdfb280a39880bad66f42b4c`; ожидается подтверждение актуальным Windows CI/CTest.

### SFZ-движок — согласованный функциональный контракт

Загрузчик должен читать SFZ-карты и обрабатывать как минимум:
- sample path и относительные пути;
- root key и key range (lokey/hikey);
- velocity range и velocity layers;
- round robin, если карта содержит соответствующие группы/метки;
- артикуляции и отдельные зоны, включая palm mute, если они размечены;
- sample offset/end, loop points, tune, pan, gain/release;
- частоту дискретизации и mono/stereo материал.

Поддержка конкретного opcode должна подтверждаться parser tests и playback tests. Наличие SFZ-файла или успешный парсинг не означает, что все opcode уже корректно звучат в runtime.

## 4. Библиотеки и лицензирование

Согласованы следующие направления поиска и проверки звукового материала:

- Meta Open Sound — Steel Guitar и Nylon Guitar; коллекции заявлены как CC0 1.0, но перед включением каждого релиза необходимо проверить его собственный LICENSE/manifest.
- FreePats — FSBS Electric Guitar Clean и другие подходящие банки; перед включением проверить лицензию конкретной версии.
- Каталог SFZ Instruments — только каталог для поиска; лицензии проверяются для каждого набора отдельно.
- Stargate Sample Pack — кандидат на проверку происхождения и лицензии, не автоматически одобренный контент.
- Собственные записи PPGU — приоритетный путь для оригинальных поп-панк артикуляций и performance-записей с письменными правами на коммерческое распространение.

Правила:
1. В заводской пакет попадают только звуки с подтверждённым правом на коммерческое использование, преобразование и распространение внутри VST3/библиотеки.
2. Для каждого набора хранить источник, автора, версию, дату получения, полный текст лицензии/атрибуцию, список файлов и SHA-256.
3. CC0/Public Domain и permissive-лицензии проверяются по полным условиям; CC BY требует точной атрибуции и соблюдения условий.
4. NC, запрет распространения, неясные/ограничительные лицензии и коммерческие библиотеки без письменного разрешения исключаются из factory package.
5. Пользователь может локально импортировать собственные звуки, но пользовательские материалы не становятся частью официального дистрибутива автоматически.
6. Коммерческие Session Guitarist, платные riff packs, чужие песни/stems и записи артистов не включаются без соответствующих прав.

Документ о лицензиях — это политика проверки, а не доказательство, что конкретная библиотека уже загружена, очищена юридически и включена в релиз.

## 5. Банки, пресеты и пользовательские файлы

Согласованная модель пользовательского контента:

- `.ppgm` — отдельный Melody preset.
- `.ppgp` — отдельный Pattern preset.
- `.ppgbank` — банк/архив пресетов с manifest.
- `.ppgstate` — необязательный полный snapshot состояния плагина для проекта DAW.

Пресеты должны иметь версию схемы, стабильный ID, имя, режим, категории/tags, параметры, артикуляции/performances и логическую ссылку на sample library/profile, а не жёсткий абсолютный путь конкретного компьютера.

- Factory presets — только для чтения.
- User presets/banks — в пользовательском каталоге AppData и не должны удаляться обновлением.
- Импорт банка: предварительный просмотр, проверка версии/структуры, защита от path traversal и чрезмерно больших архивов.
- Ошибка загрузки не должна разрушать предыдущий рабочий банк/состояние.
- Пресеты должны сохранять/восстанавливать параметры и ссылки на доступные библиотеки.

Стилевые ориентиры: Blink-182, Sum 41, Simple Plan, New Found Glory, Good Charlotte, Mest (в том числе характер “Photographs”, 2005), Angels & Airwaves, The All-American Rejects, MGK, поздний поп-панк период Avril Lavigne; также обсуждались The Offspring, Green Day, Bowling for Soup, Sugarcult и All Time Low. Используются только как музыкальные ориентиры, без копирования оригинальных записей и партий.

Наличие параметров в APVTS подтверждает exposed controls/state identifiers, но для каждого параметра отдельно требуется проверить связь с DSP/scheduler, сохранение в DAW и automation.

## 8. Производительность и потоковая загрузка

Согласованные технические требования:
- Сканирование, индексация, декодирование и загрузка банков — вне audio callback.
- Audio callback не выполняет disk I/O, декодирование, ожидание mutex, выделение/освобождение памяти.
- Безопасная публикация новых snapshots и безопасное освобождение старых, пока голоса могут их читать.
- Ограниченный RAM/page cache, bounded request queue, prefetch, pinning активных страниц и диагностируемые underruns.
- Кэш не должен входить в пользовательский пресет; пресеты ссылаются на library/sample IDs.
- Reload/unload не должен повреждать активные голоса.
- Polyphony и число активных голосов имеют явные лимиты.

**Статус потоковой архитектуры:** проектная спецификация page-cache описывает worker-based page streaming и запрет блокирующих операций в audio thread. При этом документы аудита указывают, что текущий SamplePool в проверенной конфигурации всё ещё может декодировать WAV целиком в AudioBuffer (лимит 1 GiB / 128 snapshots), а факт наличия metadata index не доказывает потоковое воспроизведение. Поэтому полную поддержку больших банков и отсутствие I/O в аудиопути нельзя объявлять принятой до проверки актуальной реализации, Windows стресс-тестов и FL Studio.

Многопоточность/multiprocessing не должна быть фиктивной галочкой: она допустима только для реальной безопасной параллельной обработки вне критического аудиопути с измеримым выигрышем.

## 9. AutoChords, Fingering и Style DNA

Согласованный функциональный объём:
- Генерация аккордов по root/scale и major/minor quality.
- Гитарные voicings, inversions и варианты аппликатуры с учётом диапазона грифа.
- Style DNA влияет на velocity, акценты, плотность chug, вероятность hammer/pull, разнос струн/strum spread и FX taste.
- Артикуляции и strum timing должны реально передаваться в sampler, а не оставаться только полями структуры.

В исходниках обнаружены первые версии AutoChords/FingeringGenerator и StyleEngine. Важный текущий риск: StyleEngine умеет рассчитывать velocity/accent и возвращает articulation/strumSpread/fxTaste, однако bug/work log отмечает, что часть этих данных ещё не подключена к выбору SFZ-зон и фактической обработке. Поэтому M4/M5 остаются незавершёнными до end-to-end проверки.

## 11. План этапов и критерии приёмки

Пользователь утвердил приоритеты:

1. **Этап 1 — M1–M5:** главный трек. Стабилизация состояния/загрузки, sampler/SFZ, MIDI/transport/scheduler, AutoChords/Fingering и Style Engine. Сначала устраняются дефекты и закрываются интеграционные тесты.
2. **Этап 2 — M6–M10:** пока идёт Этап 1, только лёгкие независимые подготовительные задачи: аудит кода, поиск и юридическая проверка библиотек, каталогизация пресетов, аудит GUI/DSP. Никаких тяжёлых интеграций, перегружающих основную сборку.
3. **Этап 3 — M11–M13:** полноценная работа начинается только после подтверждённого завершения M1–M5. Это Bank Manager/Mapping Editor/MIDI Learn, полная QA/профилирование и release packaging.

Веха не закрывается по факту наличия исходника. Нужны:
- целевые unit/regression tests;
- актуальный Windows x64 Release build и CTest;
- pluginval, где предусмотрено планом;
- ручная проверка FL Studio 20: MIDI, transport, automation, save/reopen, смена устройства, долгий playback, reload/unload;
- измерения CPU/RAM/dropouts для performance gates;
- отсутствие открытых критических багов.

## 12. Постоянные журналы и правило обновления

Каждое существенное изменение отражается в:
- `README.md` — главная краткая страница текущего статуса и ссылок;
- `jurnal.md` — хронологический журнал разработки;
- `Info.txt` — единый подробный INFO-контекст проекта;
- `docs/ЖУРНАЛ_БАГОВ_RU.md` — дефекты, root cause, fix и доказательства;
- `docs/WORK_LOG_M1_M5_INTEGRATION_RU.md` — технические детали интеграции M1–M5.

Рабочее правило: проверить требования → определить root cause → минимальное изменение → regression test → Windows CI/CTest → синхронизировать журналы. Отмена CI из-за concurrency не равна ошибке сборки. Старый зелёный запуск на другом SHA не подтверждает текущий HEAD.
