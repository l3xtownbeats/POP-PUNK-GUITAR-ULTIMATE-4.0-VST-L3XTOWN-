# PPGU — DREAMING IN NEON
## Master UI reference and implementation contract
**Дата:** 2026-11-12  
**Проект:** POP PUNK GUITAR ULTIMATE (PPGU)  
**UI skin:** POP PUNK ULTIMATE SKIN / DREAMING IN NEON  
**Ветка:** `feature/pop-punk-ultimate-skin-ui`

> Этот документ фиксирует утверждённые решения по трём визуальным референсам. Он не является доказательством реализации, сборки или тестирования. Визуальные референсы являются источником композиции; данный текст фиксирует только явно согласованные правила и ограничения.

## 1. Комплект референсов — 3/3
1. Главное окно — референс «Dreaming in Neon».
2. AutoChords — отдельный overlay-референс.
3. Совместное состояние FX EDIT + AutoChords — overlay-референс.

Все три изображения получены и считаются утверждёнными визуальными целями. Главное окно, AutoChords и совместное состояние должны воспроизводить соответствующие референсы; это не запрос на свободную переработку дизайна.

## 2. Архитектура панелей
- Дополнительные панели открываются как **overlay внутри основного окна плагина**, а не как отдельные системные окна по умолчанию.
- Поддерживаемые панели/состояния должны включать AutoChords и FX EDIT; одновременное отображение FX EDIT + AutoChords является обязательным целевым состоянием.
- У панели предусмотрены элементы управления **X (закрыть)**, **квадрат (развернуть/восстановить)** и **ON** там, где этот переключатель предусмотрен соответствующим референсом/функцией.
- Несколько overlay могут оставаться открытыми одновременно; их компоновка должна сохранять доступ к содержимому и соответствовать совместному референсу.
- Возможность открепления панели (detached/floating) — отдельная опция этапа **N5**, не обязательная часть первоначальной реализации overlay.
- Наличие кнопки или визуального состояния не означает, что функция реализована: неподключённые действия должны быть disabled.

## 3. Контракт регуляторов
- Для skin N1 принят **вариант A: реальные APVTS-подписи существующих параметров**.
- Не подменять названия действующих параметров декоративными/маркетинговыми подписями, которые не соответствуют реальной привязке.
- Добавление новых параметров не входит в N1: это отдельный тикет/этап **N6**.
- Существующие APVTS IDs и совместимость состояния сохранять; менять их только отдельным обоснованным тикетом с планом миграции.

## 4. FX EDIT — честное состояние
- Регуляторы FX EDIT и GR (gain reduction), для которых пока нет подключённых реальных параметров/измерений, должны быть **disabled**.
- Не отображать фиктивные значения, не создавать видимость активного DSP-контроля и не рисовать псевдо-GR.
- Каждый FX-контрол становится активным только после подключения к существующему/утверждённому параметру, реальному DSP-пути, корректной сериализации и тестам.
- Визуальное включение модуля должно отражать реальное состояние bypass/параметра, а не декоративную анимацию.

## 5. AutoChords — честное состояние
- AutoChords overlay входит в утверждённый визуальный комплект.
- **Preview** остаётся disabled до завершения аудио/MIDI-интеграции, способной воспроизвести фактический результат.
- Нельзя имитировать проигрывание, показывать фиктивный chord preview или выдавать статическую демонстрацию за работающую функцию.
- Управления, не связанные с реальным музыкальным движком, должны оставаться disabled до интеграции.

## 6. Статусная строка и измерения
- **Licensed** показывается только при наличии достоверного состояния лицензирования; отсутствие проверки не равно Licensed.
- **CPU** отображает только реально измеренное значение. Не использовать константы, случайные числа или неподтверждённую оценку.
- **BPM** берётся из актуального transport/tempo host либо явно обозначенного fallback-источника; не выдавать фиктивное значение за host tempo.
- Другие индикаторы должны показывать фактическое состояние соответствующего источника. При отсутствии достоверного источника — disabled/неизвестное состояние, а не выдуманные данные.

## 7. Этапность
### N1 — Skin / visual shell
- Реализовать DREAMING IN NEON поверх существующих компонентов.
- Сохранить текущие APVTS bindings, audio engine, MIDI routing, preset engine и sampler.
- Использовать вариант A для подписей регуляторов.
- Не добавлять новые параметры.

### Последующие этапы
- FX EDIT controls/GR — активировать только после реальной параметризации и измерительного пути.
- AutoChords Preview — активировать после фактической аудио/MIDI-интеграции.
- Detached panels — отдельная опция N5.
- Новые параметры — отдельный тикет N6.
- Точная детализация остальных N-фаз должна ссылаться на утверждённые проектные спецификации; этот документ не переопределяет их.

## 8. Проверка и статус
Обязательная цепочка для каждого видимого интерактивного элемента:
**действие пользователя → обработчик → реальное состояние/APVTS → реальная функция → видимый результат**.

Проверять:
- overlay lifecycle: открыть, закрыть X, развернуть/восстановить квадратом, ON/OFF;
- совместное состояние FX EDIT + AutoChords;
- resize/DPI и отсутствие недоступных/перекрытых элементов;
- APVTS state restore/automation для существующих параметров;
- disabled-состояние неподключённых контролов;
- отсутствие ложных Licensed/CPU/BPM/GR/Preview данных;
- регрессии для существующих MIDI, preset, sampler и DSP путей.

Статусы не смешивать:
- **PLANNED** — запланировано;
- **IMPLEMENTED** — исходный код реализован;
- **BUILT** — подтверждена сборка конкретного SHA;
- **TESTED** — пройдены перечисленные тесты конкретного SHA;
- **DAW VERIFIED** — подтверждена проверка в целевой DAW/окружении.

## 9. Явные non-goals этого этапа
- Не менять production source в рамках фиксации данного master prompt.
- Не добавлять новые APVTS-параметры в N1.
- Не включать неподключённые FX/GR/Preview элементы.
- Не внедрять detached OS windows в N1.
- Не заявлять CI/build/CTest/pluginval/FL Studio acceptance без результатов для точного SHA.
