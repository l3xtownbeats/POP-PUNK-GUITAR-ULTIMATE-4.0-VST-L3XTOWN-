# REV 6.0 ← 5.0 — выборочный перенос каталога

Дата: 11 ноября 2026  
Целевая ветка интеграции: `integration/rev6-5.0-catalog`  
Базовая ветка: `main`

## Принятое решение

Не выполнять merge ветки `5.0` целиком. Ветки разошлись: у `main` и `5.0` разные аудиореализации, а перенос старого PluginProcessor/PluginEditor целиком вернул бы несовместимые изменения и заблокированные функции.

В REV 6.0 выборочно переносится наиболее независимый и полезный результат 5.0 — расширенный авторский каталог пресетов и его метаданные.

## Что перенесено в этой интеграционной ветке

- Добавлен `presets/factory_bank_432.json`: 216 MELODY + 216 PATTERN профилей, 21 артист/референсная группа.
- В CMake подключён новый каталог как BinaryData.
- Browser loader расширен полями ID, artist, reference tracks, tonal target, sample profile/requirement, note behavior, status, style profile и available sound characters.
- Поиск каталога дополнен этими метаданными: теперь доступны запросы по артисту, треку, sample requirement, tonal target и стилевому профилю.
- Перенесён усиленный validator из 5.0; минимальные количества теперь читаются из `minimumPresetCounts`, а не расходятся с описанием файла.
- Windows workflow проверяет именно новый 432-профильный каталог.

## Что намеренно НЕ перенесено

- Старые `PluginProcessor.cpp/.h` из 5.0: не заменять ими REV 6.0, поскольку в main есть более новые транспортные и sampler/streaming изменения.
- Старые `PluginEditor.cpp/.h` целиком: UI 5.0 содержит функции/контролы, часть которых была отмечена как заглушки или заблокированная.
- Старый FX/audio graph целиком: перед переносом требуется сопоставление параметров, signal flow и DSP с актуальным processor.
- Палитры/skin switching 5.0 как готовую смену оболочек: там подтверждена палитра, а не полноценные resource-backed skin packs.
- Заявления о 432 готовых звучащих пресетах: каталог — авторские tonal/performance definitions. Пока sample maps и pattern performance runtime не связаны с каждой записью, это не 432 завершённых звука.

## Проверки и статус

Ветка `main` до интеграции имела успешный Windows x64 Release build, CTest, VST3 bundle validation и pluginval strictness 5 на HEAD `ae67940720dd406a0f1043c2d938d2766358053c` (Actions run 42983472326). Это baseline, не результат текущей интеграционной ветки.

Ветка 5.0 имела успешный аналогичный workflow на HEAD `4c6a78ec3862f30d6c4cc5a82afe1fe0d9ad7eb8` (Actions run 42945283886). Эти результаты не заменяют CI новой интеграционной ветки.

До объявления переноса готовым требуется:
1. Windows x64 Release configure/build.
2. Полный CTest.
3. Проверка validator на 432 entries, уникальные ID, артистов, track references и track-study coverage.
4. pluginval strictness 5.
5. Проверка preset browser в FL Studio 20: поиск по artist/track, сохранение выбранного профиля при фильтрации, отсутствие ложного сообщения о загруженном звуке.

## Следующие инженерные приоритеты

1. Получить CI для этой ветки и исправить все обнаруженные ошибки.
2. Добавить тесты на сохранение текущего выбора при изменении поискового запроса и пустой результат.
3. После проверки каталога продолжить M1–M3, прежде всего реальный путь PatternScheduler → SamplerEngine и безопасное потоковое чтение в voice render.
4. Только после M1–M3 acceptance переходить к полноценному UI/UX и skin manager.
