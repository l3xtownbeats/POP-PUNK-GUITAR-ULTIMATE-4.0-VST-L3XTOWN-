# Sample Page Cache — техническое решение

Дата: 10 ноября 2026
Статус: проектирование перед реализацией; runtime-код не изменён.

## Цель

Обеспечить воспроизведение больших WAV-библиотек без декодирования всей библиотеки в RAM. Заводской комплект вместе с пресетами ограничен 20 GB; пользовательские BANK не имеют искусственного общего лимита, но ограничены свободным местом, бюджетом кэша и числом активных голосов.

## Принятые решения

1. Metadata index остаётся отдельным этапом импорта. Сканирование не декодирует аудио.
2. Источник сэмпла хранит канонический путь, размер файла, число кадров, частоту, каналы и формат. Путь повторно проверяется при открытии.
3. Декодирование выполняется только worker-потоками. processBlock() не открывает файлы, не декодирует, не ждёт worker и не захватывает mutex.
4. WAV читается страницами фиксированного размера. Размер страницы и число страниц задаются конфигурацией; общий RAM budget имеет жёсткий предел.
5. Audio thread читает только уже опубликованные страницы через lock-free/non-blocking lookup. Cache miss возвращает тишину для недостающего участка и ставит bounded request; аудиопоток никогда не ждёт диск.
6. Запросы страниц дедуплицируются. Очередь ограничена; при переполнении запрос отбрасывается, счётчик underrun увеличивается.
7. Worker делает sequential prefetch для активного голоса и соседних страниц. Предзагрузка не должна вытеснять страницы, которые сейчас используются аудиопотоком.
8. Освобождение страниц и поколений банков выполняется не на audio thread. Для публикации и reclamation используется явный lifetime protocol (epoch/refcount handoff или эквивалент с доказанной RT-безопасностью).
9. Повторная загрузка BANK транзакционна: неудачный импорт не меняет активный BANK; старое поколение освобождается только после подтверждения, что аудиопоток больше его не использует.
10. Кэш восстанавливаемый и не входит в состав пользовательских пресетов. Пресеты ссылаются на BANK ID и относительные sample IDs, а не копируют WAV.

## Запрещённые решения

- Не увеличивать лимит SamplePool с 1 GiB до размера архива.
- Не выполнять AudioFormatReader::read, файловый I/O, mutex wait, allocation или deallocation в processBlock().
- Не возвращать указатель на страницу, которую worker может переиспользовать до окончания чтения audio thread.
- Не считать metadata index доказательством потокового воспроизведения.
- Не включать в factory package ассеты без подтверждённого права на коммерческое распространение.

## План реализации

### S1 — контракт и тестовый источник
- Ввести абстракцию sample source и фиксированные page descriptors.
- Проверить границы файла, короткие/пустые WAV, mono/stereo, 16/24/32-bit PCM и float.
- Проверить ошибку открытия/чтения и изменение файла после индексации.

### S2 — worker и bounded page cache
- Ограниченная очередь запросов, дедупликация, worker shutdown.
- Cache hit/miss, prefetch, eviction, generation lifetime.
- Стресс-тесты при одновременном запросе страниц многими голосами.

### S3 — аудиобезопасная публикация
- Неблокирующий lookup страницы.
- Отсутствие mutex/I/O/allocation/deallocation в аудиопути.
- Измерение underrun и детерминированное поведение при cache miss.

### S4 — интеграция в SamplerEngine
- Перевести Voice с прямого AudioBuffer pointer на page-backed reader.
- Сохранить SFZ offset/end/loop/tune/pan/gain/release.
- Оставить ограниченный preloaded режим для коротких one-shot сэмплов при необходимости.

### S5 — приёмка
- 100 одновременных/последовательных note hits без use-after-free и зависаний.
- Повторные reload/unload без роста RAM сверх заданного бюджета.
- Длительное воспроизведение больших файлов и библиотек.
- Cache miss stress, worker shutdown, disk error, corrupted file.
- Windows x64 Release build, CTest, pluginval и ручной тест в FL Studio 20.

## Текущий статус

В репозитории уже есть metadata-only WAV index. SamplePool всё ещё декодирует целые WAV в AudioBuffer, ограничен 1 GiB и 128 snapshots. До реализации S1–S4 потоковое воспроизведение больших BANK не поддерживается.
